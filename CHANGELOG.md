### Added

- Kimi 的 AskUserQuestion 现在能在手机上直接作答。Kimi 的 ACP 层把提问以 `session/request_permission` 形式转发（选项即答案，外加一个 Skip），网关此前把这类请求画成普通权限卡：问题文本不显示、按钮语义错位，而且回应走不通（见下条）。现在 kimi 的提问渲染为「Agent 提问你」卡片——问题原文 + 选项按钮（Skip 显示为「跳过」、不显示风险徽标），点选后 agent 立即收到答案并继续回合。时间轴上的工具行也从裸 JSON 摘要换成可读的「问题 + 选项」文本（`QuestionSummary`）。已用真实 kimi 走完网页创建会话→提问→手机作答→agent 确认的端到端验证。已知边界：提问发生在电脑端 TUI 且网关尚未接入时，Kimi 不会把已挂起的提问重新派发给事后 `session/load` 的客户端（实测确认，原 runtime 退出也不会改派），这类回合仍需在电脑端回答——网关接入后产生的新提问不受影响。
- The Go gateway answers ACP reverse requests with the correct wire shape again. Python's `acp_adapter.respond` wrapped the phone's `{optionId}`/`{cancel}` reply into ACP's nested `{outcome:{outcome:"selected"|"cancelled", optionId}}` (validating the option id against the offered options); the Go migration had lost that translation and forwarded the raw web shape. Spec agents read only the nested form — kimi's bridge dereferences `response.outcome.optionId` and resolves every raw reply into "user dismissed"/"rejected", so every kimi permission (shell approvals, plan reviews, questions) answered from the phone was silently discarded. `Session.Respond` now performs the Python translation at the single choke point both the HTTP respond route and the Jev auto-approve path go through; malformed replies keep the card answerable instead of consuming it. Jev's auto-approve additionally read the option id from an `id` key that does not exist on the wire (sending `optionId: null`) — it now reads `optionId` first, so Jev-approved turns no longer auto-reject.
- ACP agents (kimi, zcode) gain a multi-account pool with quota-driven automatic switching — the zcode-switcher integration. Accounts are imported or captured into `<dataDir>/pool/<kind>/` (kimi single-file credentials; zcode `enc:v1:` snapshots decrypted in Go — AES-256-GCM cross-verified against zcode-switcher's JS), each with live quota reads (kimi `usages` weekly + window limits including the 5-hour window; zcode billing current+balance with a BigModel monitor fallback, 429 backoff and one all-401 retry). Only the active slot is polled on a cadence (default 5 min, `GATEWAY_POOL_POLL_SECONDS`, negative disables); spare accounts are queried on demand. Manual switching gates on running turns and pending approvals (409 naming the source session), reads back slot drift into the outgoing snapshot (the official CLI rotates refresh tokens), writes atomically, reattaches live ACP sessions through `session/load` and rolls the slot back when reattach fails — zcode switches first SIGTERM the desktop app (it rewrites the slot files) and relaunch it best-effort; every attempt, refusals included, is journaled to `history.jsonl`. When a window limit is exhausted the gateway switches on its own: the passive hook (`poolQuotaHook`, first on the AutoContinue chain) prescreens suspected quota failures and re-confirms through a fresh quota read so transient 429s never trigger a switch, and the poller raises the same path past a 95% threshold. Guards derive from the journal (10-minute cooldown, ≤6 switches/hour, an account abandoned after 3 strike-outs in 24h, a window resetting within 5 minutes is waited out), the target is the candidate with the most headroom on its tightest window (ties broken by least-recently-used), and interrupted sessions resume through a dedicated `MaxSwitchResume = 3` budget that does not consume `MaxAutoContinue`. The feature defaults on (per-kind toggle persisted in `pool/settings.json`, `GATEWAY_POOL_AUTOSWITCH=0` to disable globally) and notifies through the existing channels. The web account dialog hosts one pool panel per agent — Kimi and ZCode fully operable (import, refresh, switch, auto-switch toggle, history), Codex read-only with writes redirected to the existing 账号与接入 switch flow. MiniMax/WorkBuddy are deferred until their ACP side lands.

The parser only read the missing absolutes, so every Token 用量 row parsed as 0/0 and the panel said 暂未提供 while zcode-switcher (which reads percentage) showed live numbers. The monitor normalization now synthesizes a percent window (used/limit = pct/100) whenever the absolute numbers are absent, so the row — and its 5-hour reset countdown and exhaustion gating — behaves like any other window. Verified live: 已用 94%/reset 4.5h matches zcode-switcher's complement.
- Kimi account switches stopped leaving a dead slot. The switcher renewed the target token only when locally due, so a snapshot whose chain had lost a rotation race with the desktop CLI/zcode-switcher (clock-valid but server-side dead) was written verbatim and the agent answered "Stored token for kimi-code was rejected; re-login required". The switch now always exchanges the target's refresh token before taking the slot (minting a live access token and proving the chain; a dead chain refuses the switch and marks the account reauth instead of bricking the slot), with a `/me` verification fallback when the exchange fails transiently. On top of that, when the poller notices the slot's account identity moved between ticks — a zcode-switcher switch the gateway did not perform — the gateway reloads kimi's idle live sessions (`Reconcile`), so phone chats stop dying with stale OAuth state until a gateway restart.

- Pool quota refresh now actually reaches kimi accounts. The active slot was matched by exact token chain, but the official CLI (and zcode-switcher) rotate the slot's tokens every 15 minutes, so the pool copy stopped matching within minutes and the poller silently skipped the kind — tokens stayed fresh through session use while quotas froze at import day. Slot identity now comes from the access token's `user_id` claim (exact-token matching kept as the fallback for non-JWT tokens). A second slow sweep (default hourly, `GATEWAY_POOL_POLL_ALL_SECONDS`, negative disables) refreshes every pooled account whose snapshot is older than the sweep interval — snapshots fresh off the fast loop are skipped so restarts stay cheap; sweep failures land on the account as `quotaError` and never fire the auto-switcher.
- AgentHost no longer broadcasts `session/update` notifications to every gateway connection, which cross-talked concurrent chats sharing one agent-host: updates are unicast to the connection owning the session (the mapping is registered from `session/new` responses), and `acpruntime` sessions drop notifications/requests whose sessionId does not match (zcode's lazy placeholder ids pass through Canonical).
- A cellular/Wi-Fi handoff no longer leaves the phone on a silently dead SSE: an `online` event now wakes the transport, refreshes activity, and retries a failed recent-window fill (`ChatTimeline.refill`), so the timeline recovers without a reload. The same refill runs on a foreground return.
- The list's 最近交互 timestamp now refreshes with the 5s activity poll for native-followed agents. `/api/activity` rows carry the native recency (zcode `session.time_updated`, dsh transcript mtime), and the sidebar updates the affected row's timestamp in place when its sort position is unchanged, so an active chat no longer waits for a full list reload to show a fresh time — and the 5s bumps do not re-render (or scroll-jump) the whole list.
- The read-only upgrade copy now spells out the desktop contention: the hint says to close the desktop session before 尝试接入, the disabled button explains that the desktop turn is still running, and a successful upgrade toasts that the session should not be continued in the desktop app at the same time.
- ACP branches can now be created from an already-settled turn while a newer turn is still running. The message-action handler refused every branch whenever the session's view was `active`, even though the target row's own `turnStatus` is validated later; the session-wide check is gone and the per-row rule (an in-progress target turn is still refused) remains. This is what lets the phone branch out of a long desktop-driven turn instead of staying trapped in the read-only view until it ends.
- A read-only DSH session can try to attach again. The read-only hint gained a 尝试接入 action that calls `reconnect?upgrade=1`; the gateway attempts a real handle only when the view is idle (a running desktop turn answers a hint and keeps the read-only view), and a successful load swaps the writable session in and reopens the chat. The automatic reconnect on open never triggers the upgrade.
- Stale in-progress turns no longer leave the phone on "working" forever: the native readers (zcode SQLite and the DSH transcript) mark a turn interrupted after 15 minutes without a store/transcript write, even though its `turn/end`/usage row never arrived (desktop app quit, crash or kill). A later write revives the turn.
- ZCode user attachments now reach the phone. `file` parts were ignored by the native reader, so screenshots sent in a desktop-driven zcode turn never appeared. The reader resolves the part's local path, copies it into the gateway's media directory once (macOS cleans `/var/folders`), falls back to decoding the `zcode-artifact://` data-URL copy when the temp file is unreadable under TCC, and hands it to the existing `/desktop-images` route; non-image files keep a name-only attachment.
- DSH transcript following also runs on sessions with a live ACP handle. Previously the transcript was only a fallback for sessions the desktop app refused to load, so a session opened successfully while the app was idle went stale as soon as the app drove the next turn. The dsh manager now shares one transcript reader between the live follower (`Native`) and the read-only fallback (`NativeTranscript`); the first native fold replaces the ACP replay once (native ids/attachments), and later folds keep the settled-tip dedupe. A desktop-driven turn therefore stays live on the phone whether the handle is writable or read-only.
- DSH sessions the desktop app owns now appear in the phone list with their real title and last-activity time. dsh-acp's `session/list` omits the title for a session the app currently holds and stamps a creation-time `updatedAt`, so the conversation in use showed as 未命名聊天 and sank below newer chats (the DSH app itself lists it by title). The dsh manager now fills both from the app's own read-only state — `storages/session_projcache/sessions/<id>.json` (`record.rows.title.val`, falling back to the first user message) and the session transcript's mtime (`sessions/*/<id>/session.*`, lock files ignored) — and uses that title when a session is opened, so the view header stops saying 未命名聊天. - DeepSeek (dsh) chats can send again — every message, 普通模式 included, answered 当前 Agent 不支持此工作模式 since the workMode wiring landed (2026-10-14): the generic `SetMode` validated the requested id against dsh's `modes` object, which is a permission-preset surface (read-only / workspace-write / danger-full-access) — and dsh implements no `session/set_mode` at all. The dialect override Python's `DshAdapter._set_mode` carried is now ported: the dsh profile names `ModeOptionID: collaboration_mode`, sessions stamp it at creation, `SetMode` routes to that config option through `session/set_config_option` (refused with the original message when the option is absent — dsh only advertises it while its runtime has a plan command), and the view folds `collaboration_mode.currentValue` into the collaboration slot while ignoring the permission-preset `modes` object, `current_mode_update` notifications and the `mode` config option (`DshSessionView` parity), so the composer reflects plan/default truthfully. Direct sends and queued dispatch share the fixed path; other agents are untouched. Verified against the live dsh-acp: default→plan→default switches land and the initial fold shows `default`.
- Old (non-live) codex sessions now show the same per-round file cards and ✓/✗ command badges as live ones: the store's history parser converts rollout `item_completed` payloads for `FileChange`/`CommandExecution` items into the camelCase item rows the view pipeline already consumes (`changes` keyed by path with `unified_diff`/content entries flattened to `[{path, diff|oldText, newText}]`, argv arrays joined into one command string, snake_case `exit_code`/`aggregated_output` renamed), so `buildHistoryView`'s existing annotation hook and the timeline projection carry structured `changes`/`exitCode` onto historical rows. Purely additive on the Python-parity parser: no conformance scenario feeds these payloads, so golden bytes are untouched; added files render through the ACP-style oldText/newText channel.
- The accounts panel's 切换到此接入 control works on the Go gateway again: switching is ported end to end (see Added above), `canSwitch` reflects real availability (a validated desktop executable and a switch-ready phase) instead of always reporting false with the 在桌面端操作 hint, and switch failures still surface through the panel's error line.
- Eliminated the process-fatal data races behind the gateway's whole-process crashes ("concurrent map read and map write"): message-action validation now reads the shared per-thread projection under the same `historyMu` the live-timeline fold holds (it previously read Timeline internals unlocked while SSE folds rebuilt them); `Auth.GetForClient` / `NewSession` hand out detached session snapshots so concurrent requests no longer share one mutable record; ACP catalog reads (`CommandSkills`) snapshot the advertised command list under the session lock, `SetMode` snapshots the advertised mode facts before its unlocked validation window, and `MergePending` no longer appends into the shared `session/list` cache slice; codex follower `Owner`/error reads in `Call`, `Watch` and migration are bridge-lock guarded.
- The regression gate now includes the race detector: `make test-race` runs `go test -race ./...` and `make check` chains build + vet + test + race. New concurrency coverage guards the fix: an end-to-end stress (codex follower snapshot producer racing HTTP timeline/changes/detail readers, message-action probes and an incremental SSE connection), a seeded deterministic replay (`MOBILE_BRIDGE_RACE_SEED` env to reproduce; asserts cursor semantics — epoch rotation answers resets, same-epoch diffs carry only moved rows, stale versions rewind detail — plus mirrored row counts and merged chunk texts across concurrent readers), and an ACP catalog-vs-notification-stream race test. Panics and runtime fatals were already visible in `make logs` (both launchd plists route StandardOutPath/StandardErrorPath to `~/Library/Logs/mobile-bridge-gateway.log`); verified, nothing swallowed.
- Long replies now stream to the phone with far less SSE traffic and projection CPU. The per-thread timeline projection reuses the compact encoding and digest of every row whose view inputs are unchanged, so a streaming append to the last message rebuilds only that row instead of re-cloning and re-encoding the whole view (a 500-row projection: ~2.4ms → ~0.3ms per update, ~8x faster, ~5x less allocation; projection output stays byte-identical, guarded by the conformance golden). On top of that the incremental SSE stream gained an additive `event: delta` frame: when every row move since the connection's cursor is a plain text append (strict prefix, both sides inside the untruncated 8000-char preview, tail ≤ 4000 bytes, no other field or order change), the gateway ships just `{key, version, prevVersion, append}` per row plus meta/files; any other move — new rows, edits, status flips, oversized or truncating appends, reordered history — keeps the byte-identical `changes`/`reset` frames, and the web client patches rows locally and falls back to one changes re-read whenever a delta does not line up. Long-poll tunnels are unaffected.
- Timeline projections are now locked per thread instead of behind one global mutex: each thread's projection got its own slot (`projections.go`), so a chat screen's timeline read, its SSE loop and message actions serialize only against their own thread while other chats fold concurrently. Same-thread ordering semantics are unchanged; reads for unknown threads still never materialize projections.

Reverse agent requests (e.g. `session/request_permission`) are bound to the gateway connection that owns the session, keeping permission answers on the right wire.

- The phone now preselects 完成后发送（排队） in the composer while an agent without steering support is working, so one tap on 发送 queues the message instead of showing the busy error; the choice reverts when the session goes idle and a manual override wins. Ids are now split by owning bridge, and ACP bridges report from live handles only — the poll never spawns an agent process just to paint a dot.

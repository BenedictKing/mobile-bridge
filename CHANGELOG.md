## [Unreleased]

### Added

- Goal mode is ported for codex chats — the last unported Python surface. Sending with workMode `goal` no longer falls back to a plain prompt: the objective (1–4000 chars, plain text only, local host) enters a durable goal-command ledger (`goal-commands.json`) whose state machine plans every intent against the authoritative native goal (read directly from `goals_1.sqlite` with locked-read retries, so view reads never spin an app-server), writes through the goal sidecar RPC (`thread/goal/set|clear`), re-reads to confirm and lands in `confirmed`/`failed`/`unknown` with replay semantics — a retried request id replays the recorded verdict instead of double-writing. The panel's 暂停/恢复/修改/关闭 routes ride the same machine with deterministic request ids (pause must come from active or the limited states, edit only from paused, cancel confirms by absence), a confirmed create/resume fans out the bridge-sent activation turn (localized zh/en text, stable uuid5 request id) through the queue ledger so an in-flight reply finishes first, and the cancel retires still-queued activation turns. Views carry the panel fields modes.js renders — `goal` (native row), `goalRuntimeAvailable`, `goalActivationIds` (the timeline projection hides those activation user rows) and `goalSubmission` (the pending/unconfirmed card) — and the visible queue hides activation ids. codex advertises the `goals` capability again. mcode (MiniMax Code) speaks its native goal extension the same way: workMode `goal` sends and the panel routes ride `mcode/session/goal/create|patch|clear|get` on the session's live ACP process (reads never spawn a process, writes open the session on demand), its goal/create kicks the turn off by itself so the gateway never double-starts with an activation turn, and the mcode profile advertises `goals`. Other ACP agents keep the 不支持目标模式 answer. Still sidecar-only: the desktop-owner goal transport.
- Interrupted account switches can be recovered from the phone: the panel's 恢复原接入 button (enabled only in the `interrupted` phase) rides `POST /api/accounts/switch` with `action:"recover"` and replays `rollback.json` — stop the desktop, restore the pre-switch snapshot, relaunch, verify health, flip `activeId` back and clear the record; a failed recover parks back in `interrupted` with the manual-recovery hint, and a missing record means nothing was applied (phase `failed`).
- Account switching is ported from the Python gateway: `POST /api/accounts/switch` now drives the real desktop App restart instead of answering a fixed 409. The switch requires both confirmations and a canonical UUID request id, refuses a second concurrent switch (409) and a blocked desktop — live codex turns, pending approvals and queued/uncertain submissions (Python `blockers`) — then records an idempotency ledger (`accounts/requests.json`), snapshots `config.toml`/`auth.json` (symlinks refused, refreshed tokens of the outgoing ChatGPT account written back into its own directory), builds the target account's prepared config through a short-lived app-server (`config/read` + `config/batchWrite`, so profile/forced-login/overlay limits surface before anything is applied), quits the GUI gently (osascript on macOS, CloseMainWindow on Windows, SIGTERM on Linux; never force-killed), waits for the desktop IPC endpoint to stop accepting connections, applies the prepared files, relaunches detached with `CODEX_HOME` pinned, verifies provider/identity health over RPC (35s budget) and only then flips `activeId` (with a config hash stamp). Any failure after the quit rolls everything back — restore the snapshot, relaunch, re-verify, land in `restored` with the panel error kept — while a failed rollback parks in `interrupted` (also how a crash mid-switch surfaces after a gateway restart: persisted `switch.json` phases normalize on load). Desktop discovery follows Python (`desktopExecutable` index field first, then the runtime's `.app` bundle Info.plist / platform-named ancestors), `canSwitch` is a real availability check again (validated desktop executable + a switch-ready phase) and the panel status now carries `desktopExecutable`. All process side effects go through an injectable `ProcessController` (the tests fake the desktop), so developing or testing this never restarts the user's real Codex App.

- ACP chats gain 从这里分支 / 编辑并新建分支 (message-action `fork` / `edit-fork`) — a gateway-synthesized capability that goes beyond the Python bridge, whose fork only existed for codex. The gateway creates a new session on the same agent and the source's working directory (titled 源标题 · 分支) whose first prompt carries the transcript up to the chosen turn (the turn's own exchange included; `edit-fork` stops before the turn and appends the edited text as the branch's new user question), rendered through the migrate transcript flattener with branch wording (zh/en per `uiLocale`, which the phone now sends along the action identity). The cursor row is validated under the source thread's projection slot lock (fork needs the assistant `forkable` flag, `edit-fork` the first-user `editable` flag — the Python `message_action` rules), create/prompt run only after the lock is released, and the system-generated message never carries the result-visibility convention. The child is recorded in the forks ledger (`meta.forkedFrom` links back to the source), a retried POST returns the recorded result through the shared message-action ledger instead of minting a duplicate branch, and a failed transcript dispatch reports `status:"unknown"` with the draft preserved. In-place `edit` stays codex-only and answers 400 当前 Agent 不支持编辑并重新发送，请使用编辑并新建分支. To make the controls reachable, settled ACP turns are now marked actionable on the request-private view (acpview mints every turn non-actionable — Python parity — which kept editable/forkable false forever), and every ACP agent profile now advertises the `fork` capability instead of acpViewState filtering it out (goals stay hidden).
- Per-round file result cards and a diff review panel on the phone chat screen. Codex `fileChange` items keep their per-file unified diffs and `commandExecution` items their exit codes as structured fields (bounded to 20 files and 16 000 chars per diff, clipped with a `truncated` marker) instead of vanishing into folded row text — re-attached at the httpd layer on the request-private view so the conformance-locked normalizers stay byte-identical. ACP tool calls collect `diff` content blocks (and claude-style `file_path`/`old_string`/`new_string` rawInput as a fallback) the same way, deduplicated per path with the latest text winning, and those blocks no longer serialize into the flattened output text. Activity rows with changes render per-file cards (relative path, +/− line counts, ✓/✗ exit badge on command rows); tapping a card opens a review dialog that colors unified diffs or computes a line-by-line LCS view for old/new text pairs (files beyond 2 000 lines degrade to new-content-only, long diffs paginate with 继续显示). Each turn also gains a「本轮改动 N 个文件」summary card after its last row, aggregating and deduplicating the round's files.
- Queue-send semantics are now wired into the Go gateway (previously the phone's queue controls hit a 404). `send` with `mode:"queue"` joins a durable submissions ledger (`<dataDir>/submissions.json`) and answers `{status:"queued"}`; the `queue` route performs send-now / edit / delete on the cards; queued messages dispatch automatically the moment a live ACP turn settles (chained onto the auto-continue settle hook) and through a 3s maintain pass for idle agents and codex followers. Outcome branches follow the Python oracle: a dispatch that provably never reached the agent returns to the queue (attempt ladder capped at 10, then failed), a definitive rejection marks the card failed with its error, and anything uncertain stays `unknown` — surfaced through `meta.submissions` on every live and historical timeline read, with `/api/accounts/ignore-submission` now actually marking uncertain rows ignored instead of returning a stub.
- Sessions can now be deleted from the phone: `POST /api/sessions/{id}/delete` plus a 删除会话 control in the chat details sheet. Codex threads delete natively through the short-lived app-server's `thread/delete` (never by touching `~/.codex` files; older runtimes without the method degrade to hiding with a warning); ACP threads — which have no protocol delete — are removed gateway-side only: a durable hide list (`<dataDir>/hidden-sessions.json`) filters the session list, activity dots, discovery fingerprints and all timeline reads, and the gateway drops the live agent handle. Pending queued messages of a deleted thread are dropped and the discovery revision bumps so every open list reloads.
- Branched and migrated chats now link back to their source: a fork-origin ledger (`<dataDir>/forks.json`) records child → {id, host, title} on migration and on fork creation, and timeline meta carries `forkedFrom` so the details sheet shows the 来源会话 link.
- Codex fork branches are ported: message-action `fork` / `edit-fork` copy a thread up to the chosen turn through the app-server's `thread/fork` (schema-gated like the Python `fork_copy`: the runtime must expose `lastTurnId` + `deferGoalContinuation`, the fork position and model provider are verified), carry the source's model/provider/effort/service-tier/permission settings, and `edit-fork` pushes the replacement text through the follower IPC once a desktop owner attaches — until then the draft returns to the phone instead of being lost. The `fork` capability bit is advertised again for codex (ACP agents now get it too, through the synthesized gateway-side branch above).
- Codex attachments are fixed for non-image files: they now ride the turn context's `fileAttachments` (path + label) exactly like the Python adapter, with images staying `localImage` input items — the previous `resource_link` input blocks are not part of the follower protocol and could be rejected by the desktop.
- Result visibility no longer relies on agent discipline: a new optional setting 要求 Agent 附上产物路径 (settings dialog → 结果可见, persisted to `dataDir/conventions.json` via `GET/POST /api/conventions`, default off, atomic 0600 writes) makes every phone-initiated ACP turn carry a short convention text block asking the agent to list produced/modified file paths and reference images with Markdown image syntax, so the reply's artifacts stay previewable on the phone. The block rides after the user's own text block — the timeline's user row keeps the raw message verbatim (`BeginTurn` records the original text) — and steer supplements, auto-continue resumes and Codex turns are never injected (Codex's app-server turn contract only exposes `developer_instructions` as a turn-wide replacement, not an additive channel, so the setting copy notes 仅对 ACP agents 生效). Queue dispatch that routes through the send handler or calls the shared `conventionExtras` helper follows the same rule.
- `.html`/`.htm` artifacts now preview inside the chat: markdown images and links that resolve into the `files` map render as a collapsed `<details class="artifact-preview">` card — summary shows 预览 + file name plus a 在新标签打开 link, and the sandboxed `<iframe>` (allow-scripts, no-referrer, lazy) only fetches the artifact URL when expanded (60vh, both themes). The shell CSP — the `output()` and SSE copies are now one shared constant — gained `frame-src 'self'`, and sandboxed artifact documents replace their blanket `X-Frame-Options: DENY` with CSP `frame-ancestors 'self'` so the same-origin iframe preview is actually renderable while third-party framing stays blocked.
- Chat images now open in a full-screen lightbox (new `web/image-viewer.js`): timeline attachment previews, desktop images and workspace artifact images zoom in on tap, with × / Esc / backdrop-tap to close and a 在新标签打开 button; long-press and modifier-clicks keep the original `target=_blank` behavior, and composer upload thumbnails do not trigger it. The gateway URL whitelist accepts only upload previews, desktop images and `files/{sha256}` under `/api/sessions/{id}/`.
- Agent work results are now visible on the phone. Files an agent references in markdown (`![截图](shot.png)`, `[可视化](viz.html)` — relative to the session cwd, absolute, or `file://`) resolve into servable artifacts when they sit under the cwd or the `~/.zcode/v2/visualizations` / `~/.codex/visualizations` roots: images render inline (tap for full size) and HTML opens as a sandboxed preview, both through `/api/sessions/{id}/files/{sha256}`. Images agents stream as ACP `image` content blocks are persisted under the data directory (`agent-media/<session>/`) and, like Codex desktop screenshots (`ImageView`), show as attachment thumbnails through the new `/api/sessions/{id}/desktop-images/{sha256}` route. Attachment rows ship `uploadId` (the phone's own uploads keep their preview pipeline) or `desktopId` instead of the private local path; only files the chat itself referenced are reachable, desktop images must sniff as PNG/JPEG/GIF/WebP, HTML/SVG carry a CSP sandbox so agent-authored pages never inherit the gateway's authenticated origin, and inline base64 no longer floods tool output text. This restores the Python gateway's `files` / `desktop-images` channels the Go port had dropped and extends them to ACP agents.
- OpenCode is now a supported agent (kind `opencode`): the gateway launches its built-in ACP server via `opencode acp` (env override `OPENCODE_BIN`, auto-discovered from `~/.opencode/bin` or PATH; a stale data directory alone does not count as installed). Listing, opening, creating, per-model effort variants, slash-command skills and plan mode all work like the other ACP agents — modes arrive as a `mode` config option instead of the legacy `modes` object, so `SetMode` gained a `session/set_config_option` fallback (default maps to `build`).
- Composer Enter behavior is now a setting: 回车换行（Shift+Enter 发送，default，preserves the previous behavior）or 回车发送（Shift+Enter 换行）. ⌘/Ctrl+Enter always sends in both modes, Enter pressed while composing IME candidates never sends, and the send button shows the active shortcut (⇧↵ / ↵) next to its label so the current key binding is discoverable.
- The send button is now disabled (grayed out) while the composer is empty — no text and no attachments — matching the existing submit guard; it re-enables on every keystroke, paste, attachment change, draft restore and post-send clear.

- Optional Jev auto-continue for unfinished work (web settings, persisted in `jev.json` next to `autoApprove`): when a live turn settles, the gateway can send one automatic "继续" so the agent keeps going. Unexpected interruptions (prompt timeout, process exit, truncated `max_tokens` output) resume even without a Jev key; with a key, every settled turn is judged for completeness (typed questions: complete / stop reason / should-resume, ≥ 0.8 confidence). Quota or billing exhaustion never continues — a deterministic keyword scan (额度不足 / usage limit / 429 …) runs before and below the Jev verdict — and neither do user stops, pending questions/approvals, active native goals, or chats with queued messages. Any human message, queue action, approval answer or form reply re-arms the budget of at most 5 consecutive auto-continues; the resume itself is a normal ledger submission (`autoContinue` marker, deterministic id) so it stays visible and idempotent.
- ACP agents can now ask the phone structured questions: the gateway advertises `elicitation.form` at the ACP handshake, so ZCode / DeepSeek / Claude wrappers forward AskUserQuestion-style dialogs as one form card (single-select dropdowns, multi-select checkboxes, free-text companions) instead of refusing with "the ACP client does not support form elicitation". Answers validate against the form schema and reply as accept/decline/cancel; interrupting a pending question answers cancel, and unsupported schemas still point to the desktop.
- Queued messages are now dispatched the moment the running turn ends (the maintenance loop is kicked on turn completion, approval answers and reconnects) instead of waiting out the ACP bridges' up-to-30s idle backoff.
- Failed queued sends are no longer lost: a prompt that provably never reached the agent returns to the queue (with a retry cap), a definitive agent-side rejection or validation failure marks the row failed with its error, and the queue card offers 重试发送 / 修改 / 删除.
- Every Jev auto-approval evaluation is now a single-line audit log in the gateway log (`make logs`, grep `Jev 审批`): agent/session/request ids, the method, the Jev verdict (risk / reversibility / confidence / recommendation), the machine-readable outcome (why it did or did not auto-approve, e.g. `risk_too_high`, `assess_failed`, `auto_approved`), the native response sent, and a capped card subject. API keys never appear and commands are logged only as a truncated prefix. The approval questions also regained the typed rubric the Python gateway sent (risk rubric, reversibility criteria, decision-specific recommendation options) instead of bare prompt strings.
- The Jev auto-continue switch is now wired into the Go gateway's ACP runtime: a settled turn (completion, failure or idle timeout) on a watched chat is judged for resume — deterministic interruption recovery works without a key, with a key the typed completeness verdict decides — and the automatic "继续" rides the same prompt path under the 5-consecutive budget, re-armed by any human message, steer, approval answer or form reply. Codex-native sessions keep manual continuation for now.

### Changed / Fixed

- Old (non-live) codex sessions now show the same per-round file cards and ✓/✗ command badges as live ones: the store's history parser converts rollout `item_completed` payloads for `FileChange`/`CommandExecution` items into the camelCase item rows the view pipeline already consumes (`changes` keyed by path with `unified_diff`/content entries flattened to `[{path, diff|oldText, newText}]`, argv arrays joined into one command string, snake_case `exit_code`/`aggregated_output` renamed), so `buildHistoryView`'s existing annotation hook and the timeline projection carry structured `changes`/`exitCode` onto historical rows. Purely additive on the Python-parity parser: no conformance scenario feeds these payloads, so golden bytes are untouched; added files render through the ACP-style oldText/newText channel.
- The accounts panel's 切换到此接入 control works on the Go gateway again: switching is ported end to end (see Added above), `canSwitch` reflects real availability (a validated desktop executable and a switch-ready phase) instead of always reporting false with the 在桌面端操作 hint, and switch failures still surface through the panel's error line.
- Eliminated the process-fatal data races behind the gateway's whole-process crashes ("concurrent map read and map write"): message-action validation now reads the shared per-thread projection under the same `historyMu` the live-timeline fold holds (it previously read Timeline internals unlocked while SSE folds rebuilt them); `Auth.GetForClient` / `NewSession` hand out detached session snapshots so concurrent requests no longer share one mutable record; ACP catalog reads (`CommandSkills`) snapshot the advertised command list under the session lock, `SetMode` snapshots the advertised mode facts before its unlocked validation window, and `MergePending` no longer appends into the shared `session/list` cache slice; codex follower `Owner`/error reads in `Call`, `Watch` and migration are bridge-lock guarded.
- The regression gate now includes the race detector: `make test-race` runs `go test -race ./...` and `make check` chains build + vet + test + race. New concurrency coverage guards the fix: an end-to-end stress (codex follower snapshot producer racing HTTP timeline/changes/detail readers, message-action probes and an incremental SSE connection), a seeded deterministic replay (`MOBILE_BRIDGE_RACE_SEED` env to reproduce; asserts cursor semantics — epoch rotation answers resets, same-epoch diffs carry only moved rows, stale versions rewind detail — plus mirrored row counts and merged chunk texts across concurrent readers), and an ACP catalog-vs-notification-stream race test. Panics and runtime fatals were already visible in `make logs` (both launchd plists route StandardOutPath/StandardErrorPath to `~/Library/Logs/mobile-bridge-gateway.log`); verified, nothing swallowed.
- Long replies now stream to the phone with far less SSE traffic and projection CPU. The per-thread timeline projection reuses the compact encoding and digest of every row whose view inputs are unchanged, so a streaming append to the last message rebuilds only that row instead of re-cloning and re-encoding the whole view (a 500-row projection: ~2.4ms → ~0.3ms per update, ~8x faster, ~5x less allocation; projection output stays byte-identical, guarded by the conformance golden). On top of that the incremental SSE stream gained an additive `event: delta` frame: when every row move since the connection's cursor is a plain text append (strict prefix, both sides inside the untruncated 8000-char preview, tail ≤ 4000 bytes, no other field or order change), the gateway ships just `{key, version, prevVersion, append}` per row plus meta/files; any other move — new rows, edits, status flips, oversized or truncating appends, reordered history — keeps the byte-identical `changes`/`reset` frames, and the web client patches rows locally and falls back to one changes re-read whenever a delta does not line up. Long-poll tunnels are unaffected.
- Timeline projections are now locked per thread instead of behind one global mutex: each thread's projection got its own slot (`projections.go`), so a chat screen's timeline read, its SSE loop and message actions serialize only against their own thread while other chats fold concurrently. Same-thread ordering semantics are unchanged; reads for unknown threads still never materialize projections.
- The settings dialog now has one 保存 button for every server-persisted setting: Jev (key, endpoint, model, proxy, auto-approve, auto-continue) and the global notification defaults stage locally and commit together, replacing the per-control instant saves. The Jev API key shows as a capsule chip sitting inside the input at the text position (masked value, × on the capsule removes it locally and reopens the field for a new key; the clear only reaches the gateway on 保存). Appearance and language stay browser-local and immediate; closing the dialog without saving discards staged server-side changes.
- AgentHost now multiplexes concurrent gateway connections instead of letting each new ACP socket replace the previous one: opening a Kimi chat fires `initialize`, `session/load` and `session/list` on parallel connections, and responses are routed back to the originating connection by per-connection request-id maps, so none of them time out anymore. Reverse agent requests (e.g. `session/request_permission`) are bound to the gateway connection that owns the session, keeping permission answers on the right wire.
- Collapsed activity rows (commands, tool calls, thought summaries) now keep a three-line preview instead of hiding or flooding the timeline; expanding still shows the full text with lazy loading.
- The phone now preselects 完成后发送（排队） in the composer while an agent without steering support is working, so one tap on 发送 queues the message instead of showing the busy error; the choice reverts when the session goes idle and a manual override wins. The busy error itself names the actual agent instead of always saying "Codex".
- The chat list's running / completed dots work for ACP sessions again: `/api/activity` previously routed every local id to the Codex bridge, which silently dropped ZCode / Kimi / Claude / DeepSeek sessions, so their status markers never showed. Ids are now split by owning bridge, and ACP bridges report from live handles only — the poll never spawns an agent process just to paint a dot.
- Kimi sessions now support Skill selection in the phone UI: skills advertised by the agent as ACP slash commands appear in the picker, and the chosen skill is sent as a leading `/<command>` in the message (one skill per message).
- Optional Jev (TypeSafe AI) advisory triage for manual permission confirmations: each approval card gets a risk level, reversibility, confidence, and a starred suggested option, and the riskiest pending confirmations sort first. Jev only annotates and ranks — approvals still require an explicit tap, and unconfigured gateways keep the deterministic local labels. The API key, endpoint, and model are editable in the web settings dialog (persisted to `jev.json`, masked readback, live effect without a gateway restart); env vars remain launch-time defaults and an explicit key clear disables Jev even when they are set.
- ACP agents that archive sub-agents as independent on-disk sessions are now discoverable: kimi session directories (`state.json` + per-agent wire logs), zcode (`acp-lazy-sessions.json` mapping + `cli/agents` transcripts), and claude (`subagents/` sidechain files) all feed the same timeline activity rows, read-only with size caps and mtime caching.
- Periodic session discovery (`bridge/discovery.py`): a background loop re-reads every agent's native session list every 30 seconds while at least one client is polling `/api/activity`, versions identity/title/project changes into a `listRevision`, and ships that revision with activity rows so the phone list reloads on its own when a chat is started outside the web UI (terminal, desktop App). ACP `session/list` caches are force-refreshed by the loop; with nobody watching for two minutes the loop pauses instead of spawning agent processes. SSH remote lists stay request-driven.

### Changed / Fixed

- Plan (todo) panels now show completion state: ACP plan snapshots fold into one live panel per turn, entries render as a checklist with ✓/strikethrough for completed, ▸ for in-progress and ○ for pending, and the collapsed heading shows a `done/total` count (plus ✓ when everything is done) so a finished plan is recognizable at a glance.
- ACP prompt timeouts are now idle-based: active `session/update` traffic or a pending permission request no longer counts toward the limit, and an idle-expired turn is cancelled agent-side (`session/cancel` plus cancelled answers to pending approvals) so later messages are not rejected by an orphaned turn.
- Live chat updates now stream over incremental SSE (ready/changes/reset frames with `epoch.sequence` cursor resume); the web client uses one transport module for SSE and long-polling, with capped reconnect backoff and definitive logout on auth expiry. Legacy full-state SSE and the polling endpoints stay byte-compatible.
- Queued messages can now be sent immediately when idle, edited, or deleted; automatic dispatch uses the latest edited content.
- Updated queue API documentation and added regression coverage for queue actions and edit/dispatch races.
- Cross-agent migration can create a target session for an unmatched local project and exposes target capability metadata in timeline responses.
- Upload storage accepts path-safe Agent-native session identifiers, and the mobile copy dialog layout keeps long content scrollable.
- English UI now translates native list, send-mode, and work-mode options; migration documentation matches local and remote directory behavior.
- Child-agent transcripts now preserve nested ACP output, Codex child rollouts, agent identity, status, and command output.
- The per-chat queue on/off toggle is removed: queueing is always available, and the composer's send-mode selector is the single entry point.
- Fixed duplicate zcode chat entries: the lazy placeholder session is now withdrawn from the chat list once its materialized backend `sess_*` session is listed, and `sess_*` URLs reopen after a page refresh.
- DeepSeek Harness exposes its native permission modes through the phone UI; other ACP `mode` options remain untouched when they represent collaboration modes, and Codex retains desktop-owned permission policy.
- Affected files: `bridge/jev.py`, `bridge/agents/native_subagents.py`, `bridge/service.py`, `bridge/discovery.py`, `bridge/agents/{kimi,zcode,claude}.py`, `web/`, and related tests.

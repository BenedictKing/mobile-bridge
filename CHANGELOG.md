## [Unreleased]

### Added

- Agent work results are now visible on the phone. Files an agent references in markdown (`![截图](shot.png)`, `[可视化](viz.html)` — relative to the session cwd, absolute, or `file://`) resolve into servable artifacts when they sit under the cwd or the `~/.zcode/v2/visualizations` / `~/.codex/visualizations` roots: images render inline (tap for full size) and HTML opens as a sandboxed preview, both through `/api/sessions/{id}/files/{sha256}`. Images agents stream as ACP `image` content blocks are persisted under the data directory (`agent-media/<session>/`) and, like Codex desktop screenshots (`ImageView`), show as attachment thumbnails through the new `/api/sessions/{id}/desktop-images/{sha256}` route. Attachment rows ship `uploadId` (the phone's own uploads keep their preview pipeline) or `desktopId` instead of the private local path; only files the chat itself referenced are reachable, desktop images must sniff as PNG/JPEG/GIF/WebP, HTML/SVG carry a CSP sandbox so agent-authored pages never inherit the gateway's authenticated origin, and inline base64 no longer floods tool output text. This restores the Python gateway's `files` / `desktop-images` channels the Go port had dropped and extends them to ACP agents.
- OpenCode is now a supported agent (kind `opencode`): the gateway launches its built-in ACP server via `opencode acp` (env override `OPENCODE_BIN`, auto-discovered from `~/.opencode/bin` or PATH; a stale data directory alone does not count as installed). Listing, opening, creating, per-model effort variants, slash-command skills and plan mode all work like the other ACP agents — modes arrive as a `mode` config option instead of the legacy `modes` object, so `SetMode` gained a `session/set_config_option` fallback (default maps to `build`).
- Composer Enter behavior is now a setting: 回车换行（Shift+Enter 发送，default，preserves the previous behavior）or 回车发送（Shift+Enter 换行）. ⌘/Ctrl+Enter always sends in both modes, Enter pressed while composing IME candidates never sends, and the send button shows the active shortcut (⇧↵ / ↵) next to its label so the current key binding is discoverable.
- The send button is now disabled (grayed out) while the composer is empty — no text and no attachments — matching the existing submit guard; it re-enables on every keystroke, paste, attachment change, draft restore and post-send clear.

- Optional Jev auto-continue for unfinished work (web settings, persisted in `jev.json` next to `autoApprove`): when a live turn settles, the gateway can send one automatic "继续" so the agent keeps going. Unexpected interruptions (prompt timeout, process exit, truncated `max_tokens` output) resume even without a Jev key; with a key, every settled turn is judged for completeness (typed questions: complete / stop reason / should-resume, ≥ 0.8 confidence). Quota or billing exhaustion never continues — a deterministic keyword scan (额度不足 / usage limit / 429 …) runs before and below the Jev verdict — and neither do user stops, pending questions/approvals, active native goals, or chats with queued messages. Any human message, queue action, approval answer or form reply re-arms the budget of at most 5 consecutive auto-continues; the resume itself is a normal ledger submission (`autoContinue` marker, deterministic id) so it stays visible and idempotent.
- ACP agents can now ask the phone structured questions: the gateway advertises `elicitation.form` at the ACP handshake, so ZCode / DeepSeek / Claude wrappers forward AskUserQuestion-style dialogs as one form card (single-select dropdowns, multi-select checkboxes, free-text companions) instead of refusing with "the ACP client does not support form elicitation". Answers validate against the form schema and reply as accept/decline/cancel; interrupting a pending question answers cancel, and unsupported schemas still point to the desktop.
- Queued messages are now dispatched the moment the running turn ends (the maintenance loop is kicked on turn completion, approval answers and reconnects) instead of waiting out the ACP bridges' up-to-30s idle backoff.
- Failed queued sends are no longer lost: a prompt that provably never reached the agent returns to the queue (with a retry cap), a definitive agent-side rejection or validation failure marks the row failed with its error, and the queue card offers 重试发送 / 修改 / 删除.
- Every Jev auto-approval evaluation is now a single-line audit log in the gateway log (`make logs`, grep `Jev 审批`): agent/session/request ids, the method, the Jev verdict (risk / reversibility / confidence / recommendation), the machine-readable outcome (why it did or did not auto-approve, e.g. `risk_too_high`, `assess_failed`, `auto_approved`), the native response sent, and a capped card subject. API keys never appear and commands are logged only as a truncated prefix. The approval questions also regained the typed rubric the Python gateway sent (risk rubric, reversibility criteria, decision-specific recommendation options) instead of bare prompt strings.
- The Jev auto-continue switch is now wired into the Go gateway's ACP runtime: a settled turn (completion, failure or idle timeout) on a watched chat is judged for resume — deterministic interruption recovery works without a key, with a key the typed completeness verdict decides — and the automatic "继续" rides the same prompt path under the 5-consecutive budget, re-armed by any human message, steer, approval answer or form reply. Codex-native sessions keep manual continuation for now.

### Changed / Fixed

- The settings dialog now has one 保存 button for every server-persisted setting: Jev (key, endpoint, model, proxy, auto-approve, auto-continue) and the global notification defaults stage locally and commit together, replacing the per-control instant saves. The Jev API key shows as a capsule chip sitting inside the input at the text position (masked value, × on the capsule removes it locally and reopens the field for a new key; the clear only reaches the gateway on 保存). Appearance and language stay browser-local and immediate; closing the dialog without saving discards staged server-side changes.
- AgentHost now multiplexes concurrent gateway connections instead of letting each new ACP socket replace the previous one: opening a Kimi chat fires `initialize`, `session/load` and `session/list` on parallel connections, and responses are routed back to the originating connection by per-connection request-id maps, so none of them time out anymore. Reverse agent requests (e.g. `session/request_permission`) are bound to the gateway connection that owns the session, keeping permission answers on the right wire.
- Collapsed activity rows (commands, tool calls, thought summaries) now keep a three-line preview instead of hiding or flooding the timeline; expanding still shows the full text with lazy loading.
- The phone now preselects 完成后发送（排队） in the composer while an agent without steering support is working, so one tap on 发送 queues the message instead of showing the busy error; the choice reverts when the session goes idle and a manual override wins. The busy error itself names the actual agent instead of always saying "Codex".
- The chat list's running / completed dots work for ACP sessions again: `/api/activity` previously routed every local id to the Codex bridge, which silently dropped ZCode / Kimi / Claude / DeepSeek sessions, so their status markers never showed. Ids are now split by owning bridge, and ACP bridges report from live handles only — the poll never spawns an agent process just to paint a dot.
- Kimi sessions now support Skill selection in the phone UI: skills advertised by the agent as ACP slash commands appear in the picker, and the chosen skill is sent as a leading `/<command>` in the message (one skill per message).
- Optional Jev (TypeSafe AI) advisory triage for manual permission confirmations: each approval card gets a risk level, reversibility, confidence, and a starred suggested option, and the riskiest pending confirmations sort first. Jev only annotates and ranks — approvals still require an explicit tap, and unconfigured gateways keep the deterministic local labels. The API key, endpoint, and model are editable in the web settings dialog (persisted to `jev.json`, masked readback, live effect without a gateway restart); env vars remain launch-time defaults and an explicit key clear disables Jev even when they are set.
- ACP agents that archive sub-agents as independent on-disk sessions are now discoverable: kimi session directories (`state.json` + per-agent wire logs), zcode (`acp-lazy-sessions.json` mapping + `cli/agents` transcripts), and claude (`subagents/` sidechain files) all feed the same timeline activity rows, read-only with size caps and mtime caching.
- Periodic session discovery (`bridge/discovery.py`): a background loop re-reads every agent's native session list every 30 seconds while at least one client is polling `/api/activity`, versions identity/title/project changes into a `listRevision`, and ships that revision with activity rows so the phone list reloads on its own when a chat is started outside the web UI (terminal, desktop App). ACP `session/list` caches are force-refreshed by the loop; with nobody watching for two minutes the loop pauses instead of spawning agent processes. SSH remote lists stay request-driven.

### Changed / Fixed

- Plan (todo) panels now show completion state: ACP plan snapshots fold into one live panel per turn, entries render as a checklist with ✓/strikethrough for completed, ▸ for in-progress and ○ for pending, and the collapsed heading shows a `done/total` count (plus ✓ when everything is done) so a finished plan is recognizable at a glance.
- ACP prompt timeouts are now idle-based: active `session/update` traffic or a pending permission request no longer counts toward the limit, and an idle-expired turn is cancelled agent-side (`session/cancel` plus cancelled answers to pending approvals) so later messages are not rejected by an orphaned turn.
- Live chat updates now stream over incremental SSE (ready/changes/reset frames with `epoch.sequence` cursor resume); the web client uses one transport module for SSE and long-polling, with capped reconnect backoff and definitive logout on auth expiry. Legacy full-state SSE and the polling endpoints stay byte-compatible.
- Queued messages can now be sent immediately when idle, edited, or deleted; automatic dispatch uses the latest edited content.
- Updated queue API documentation and added regression coverage for queue actions and edit/dispatch races.
- Cross-agent migration can create a target session for an unmatched local project and exposes target capability metadata in timeline responses.
- Upload storage accepts path-safe Agent-native session identifiers, and the mobile copy dialog layout keeps long content scrollable.
- English UI now translates native list, send-mode, and work-mode options; migration documentation matches local and remote directory behavior.
- Child-agent transcripts now preserve nested ACP output, Codex child rollouts, agent identity, status, and command output.
- The per-chat queue on/off toggle is removed: queueing is always available, and the composer's send-mode selector is the single entry point.
- Fixed duplicate zcode chat entries: the lazy placeholder session is now withdrawn from the chat list once its materialized backend `sess_*` session is listed, and `sess_*` URLs reopen after a page refresh.
- DeepSeek Harness exposes its native permission modes through the phone UI; other ACP `mode` options remain untouched when they represent collaboration modes, and Codex retains desktop-owned permission policy.
- Affected files: `bridge/jev.py`, `bridge/agents/native_subagents.py`, `bridge/service.py`, `bridge/discovery.py`, `bridge/agents/{kimi,zcode,claude}.py`, `web/`, and related tests.

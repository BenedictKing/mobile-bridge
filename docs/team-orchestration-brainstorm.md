# 团队编排与事项视图头脑风暴

状态：设计建议，尚未实现；2026-11-11。

## 1. 用户对象与执行对象

- Issue 是用户要完成的事，也是画布、看板、侧栏进度的共同对象。
- 原话是需求证据，允许多对多关联；删除单个 Issue 不删除共享原话。
- Run 是一次执行记录，一个 Issue 可经历多次修订 Run，一个 Run 可服务多个 Issue。
- 看板默认展示 Issue；Run 留作事项详情中的执行历史，不能拿历史执行数量充当事项数量。
- 删除、取消执行、关闭追踪、撤销文件修改是不同动作，不互相隐含。

## 2. 按任务需要选择流程

| 类型 | 默认流程 |
| --- | --- |
| 简单咨询 | 澄清必要信息 → 查证 → 回答 |
| 调查分析 | 分头取证 → 交叉核验 → 综合结论 |
| 单点修改 | 检查现状 → 小计划 → 实现 → 定向验证 |
| 复杂实现 | 调研 → 核验 → 计划 → 并行实现 → 集成 → 验证与审查 → 修复复验 → 交付 |
| 外部操作 | 检查现状 → 可审阅操作方案 → 必要授权 → 执行 → 核实结果 |

不为凑人数拆任务。成员不足时顺序执行，阶段和证据要求保留。

## 3. 阶段产出与推进条件

- 调研：仓库现状、用户约束、参考资料、许可证、数据来源、接口与环境。
- 核验：来源是否权威和适用、版本是否一致、关键假设能否通过最小实验验证；明确未知项。
- 计划：保留原始目标，列出范围、接口、任务依赖、写入边界、验收方式与回滚策略。
- 实现：每个任务必须有明确输入、可观察输出、负责人、依赖和允许修改范围。
- 集成：接收各分支成果，检查接口一致、冲突、迁移和配置兼容性。
- 验证：用真实行为与失败路径证明需求覆盖，区别代码失败和环境未就绪。
- 审查：由未实现对应改动的成员评审；不能仅转述实现者的“测试通过”。
- 交付：列出已完成、未完成、测试证据、限制和需要用户操作的事项。

资料未核实就不得把关键假设当作实现前提。计划不是必须人工批准的表单。

## 4. 并行与写入协调

- 只并行依赖已经满足的任务；先约定接口，再拆前后端或独立模块。
- 同文件写入默认串行；可用独立工作区时仍需指定集成人和整体验证。
- 测试成员可先准备验收用例，但不能在实现前声称验收通过。
- 审查可以按完成模块提前开始，最终仍须检查集成后的版本。
- 缺失成员能力、账号不可用或预算不足时缩减并发，不能把任务默默交给不适合的角色。

## 5. 失败、修订与证据失效

- 调研无结论：记录证据缺口；只有影响关键决策时向用户提具体问题。
- 实现失败：只阻塞依赖该产物的分支，无关分支继续。
- 审查发现问题：建立指向原任务的修复项；不能重跑整个团队掩盖问题。
- 同类失败重复出现：限制重试次数和消耗，改变方法或停靠，不无限循环。
- 发送结果未知：按派发身份核对会话证据，不能按文本相似度认领，也不能自动重发。
- 网关重启：恢复已持久化计划、派发身份和阶段状态；不能重新生成一套冲突任务。
- 用户追加要求：区分补充信息、范围变更和独立事项；显式更新计划版本与受影响依赖。
- 代码、配置或数据发生变化：仅重做受影响验证；过期证据不能继续证明当前交付。
- 工作区被用户或其他 Agent 修改：检测冲突，保留外部修改，不强制覆盖或自动回滚。

## 6. 共享事项与共享 Run

- 不能把共享 Run 的全部任务进度直接当作每个 Issue 的完成进度。
- 建立 Issue → 目标条件 → 任务/证据的明确映射，无法归属时展示未知。
- 同一任务可服务多个 Issue，但取消某个 Issue 不得隐式取消其他事项需要的任务。
- 第一版若无法安全拆分共享执行，拒绝自动取消并解释原因，等待执行结束再删除。
- 删除后的 Issue 不应在事项看板再次出现；执行记录在独立历史入口保留。
- 对现有以 Run 为对象的看板，需要明确迁移策略，不能只前端隐藏同名行。

## 7. 用户介入与权限

- 系统负责生成计划、完成条件与检查配置；用户只处理目标取舍、必要凭据和真实授权。
- 用户确认与系统验证分离：用户满意不等于测试通过，测试通过也不自动代表满足需求。
- 不因流水线阶段变化重复请求已有授权；生产变更、发布及破坏性动作遵循实际权限。
- 显示具体阻塞对象和下一步；内部审查派发不能出现在用户消息的发送失败区域。

## 8. 第一版建议与验证

- 先统一 Issue 与 Run 的对象关系及看板口径，再增加阶段展示。
- 在现有调度 DAG 上增加阶段、产出与证据关联，沿用派发幂等和重启恢复机制。
- 负责人按任务复杂度选流程；服务端校验关键依赖，不能只依赖提示词让 Agent 自觉遵守。
- 计划和证据随版本持久化，图节点展示实际任务与阶段，而不是装饰性的固定步骤。
- 验证矩阵覆盖：咨询、单点修改、并行实现、共享任务、缺成员、环境失败、审查返修、重启、追加需求、取消和发送未知。
- 交付门禁覆盖：计划前不得派发依赖计划的实现；重复事件不重复派发；验证失效后不得展示通过；删除不影响共享原话或其他事项。

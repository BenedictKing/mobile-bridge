# 会话迁移：图片传递转录方案评估备忘

> 日期：2026-11-27
> 状态：调研结论，未立项；仓库代码未改动。
> 关联：`docs/session-migration-and-gateway-compaction.md`（第 8 节转录预算）

## 1. 问题

会话迁移目前以纯文本转录发给目标 Agent，预算见 `internal/httpd/migrate.go:132` 的 `migrationBudgets`：

| 范围 | 消息数 | 总字符 | 单条字符 |
| --- | --- | --- | --- |
| `main` | 50 | 60000 | 6000 |
| `full` | 500 | 90000 | 12000 |
| `latest` | 12 | 40000 | 20000 |

本次要回答的问题：把转录渲染成图片发给目标 Agent，能否用更少的 token 带更多内容，而且模型还能读准。

## 2. 实验方法

- 样本：用仓库内容拼接出接近真实转录的文本，包含中文问答、Go 代码和 git 输出，共约 87k 字符。按 OpenAI `o200k_base` 分词约 35.4k token。
- 渲染：Pillow 灰度渲染，字体 Hiragino Sans GB（macOS 自带），按字符宽度自动换行，分别测 9 / 11 / 13 / 14px 字号。
- 图片 token 的估算方式：
  - Claude：单图最大约 2576×1456，按 `宽×高/750` 估算，该尺寸约 4784 token。
  - OpenAI high detail：先缩放到长边不超过 2048、短边不超过 768，再按 512px tile 计费（每块 170，另加 85）。
- 可读性：由模型亲自读图，逐行与原文核对局部裁剪图；同时模拟了 OpenAI 的缩放效果。

## 3. 实测结果

| 方案 | 单图容纳文本 | 图片 token | 压缩比 | 可读性 |
| --- | --- | --- | --- | --- |
| Claude 2576×1456，14px | 10.4k tok | 4784 | 2.2× | 清晰 |
| Claude 2576×1456，11px | 17.3k tok | 4784 | **3.6×** | 可读，抽查段落逐行核对无误 |
| Claude 2576×1456，9px | 19.2k tok | 4784 | 4.0× | 勉强，细小汉字易认错 |
| OpenAI high detail，768×2048 竖条，13px | 5.3k tok | ~1445 | 3.6× | 清晰 |
| 2576 宽图直接给 OpenAI | — | 1105 | — | **不可读**，被缩到 1359×768 |

要点：

- 图片大约能省 50–75% 的 token，"同样预算装更多内容"这一点成立。
- 收益的最佳点在 11px 左右。再缩小字号，容量几乎不再增加，可读性却明显下降。
- Codex（OpenAI）会强制缩放，Claude 用的大图给它会糊掉。两边必须分别排版，不能共用一张图。

## 4. 结论与不采纳为默认方案的理由

**结论：不把迁移整体改成图片传递。** 最多做成可选的"历史压缩"补充（见第 5 节）。

1. **收益小且只有一次。** `full` 最多 90k 字符，约 35–45k token。这部分只在目标会话第一轮输入，之后会命中 prompt cache。即使省下 2–3 万 token，也只是一次性的收益。
2. **文本变成有损。** 路径、函数名、提交哈希、ID 存在被认错的风险，而这些恰恰是转录里最关键的信息。目标 Agent 也无法对图里的内容做搜索、复制或精确引用。
3. **与现有契约冲突。** 设计文档第 8 节规定了字符和字节预算，并要求"发生裁剪时必须标明"。换成图片后，预算口径和裁剪标注都要重新定义，"未发送消息"的附加规则也一样。
4. **适配成本高。** 通道本身已经具备：
   - Codex 走 `localImage` 附件（`internal/acpview/view.go:948`）；
   - ACP 由 `internal/acpadapter/acpadapter.go:56` 按 `promptCapabilities.image` 判断是否支持图片。

   但 Claude 和 OpenAI 需要两套排版。不支持图片的 ACP Agent 必须回退到纯文本，测试面会随之翻倍。

## 5. 若要试点：最小可行方案

- **触发**：仅限 `full` 范围，且历史超出文本预算、即将被裁剪时。
- **内容**：把**本该被裁掉的早期对话正文**渲染成 1–2 张图附上，不再直接丢弃。
- **保留文本**：最近几轮、代码、命令、路径、ID、未发送消息、用户后续指示。
- **排版**：按目标 Agent 分别出图。Claude 用 2576×1456、11px；OpenAI 用 768×2048 竖条、13px。
- **回退**：目标 Agent 不支持图片时，维持现有的裁剪和标注逻辑。
- **标注**：在转录正文中说明"以下早期历史以图片附上，内容可能有识别误差"。
- **流程**：按项目的文档先行约定，先更新 `session-migration-and-gateway-compaction.md` 第 8 节和第 12 节，再动代码。

## 6. 未核实事项与复现

未核实：

- OpenAI 的图片 token 用的是老版 tile 计费公式估算，新模型实际怎么计费没有验证。
- 文本 token 用 `o200k` 代替统计。Claude 的分词器对中文和代码通常更费 token，所以对 Claude 来说实际压缩比可能略高。
- 可读性只做了抽样人工核对，没有做大样本的字符级准确率统计。

复现：实验脚本和产物位于 `/tmp/imgmig`（临时目录，重启后可能丢失）。

```bash
python3 -m venv /tmp/imgmig/venv
/tmp/imgmig/venv/bin/pip install tiktoken pillow
/tmp/imgmig/venv/bin/python -I /tmp/imgmig/scripts/exp.py "<repo>" /tmp/imgmig/out
```

# 聊天、时间线与消息操作

状态：现行特性基准。

## 1. 范围与展示契约

本文覆盖聊天列表进入会话后的历史、实时内容、消息操作、审批、附件和文件展示。

1. 用户、助手、工具、思考、错误、审批和网关状态记录是不同语义，不得混成普通聊天正文。
2. 用户消息、错误、待确认请求和关键网关状态在关闭“执行过程”后仍须保留；思考和工具活动分别受显示设置控制。
3. 正在生成的回复更新原消息，不重复追加；历史补页保持阅读位置和稳定消息键。
4. 时间线只展示有界预览，完整正文、工具输出和差异按需读取；本地资源不依赖外部 CDN。
5. 内部提醒、协议信封和不应公开的原始路径不能未经处理直接暴露到页面。
6. Agent 以用户回合注入的后台任务通知（Kimi `origin=task`，正文为 `<notification …>` 包裹的纯文本）展示为可折叠的“后台任务通知”记录：标题取 `Title`，按 `Severity` 着色，其余字段作为正文；不显示原始标签，不进入用户消息跳转列表，也不提供复制、编辑或分支。闭合标签后还有其他正文的文本仍按普通用户消息处理。
7. Claude 后台命令启动后，按任务 ID 关联原 Bash 工具调用并展示始终可见的“后台任务 · 进行中”状态；完成通知更新同一记录为成功、失败或结果未知，并展示安全摘要。任务通知不得伪装成用户输入、进入用户消息跳转或触发新的模型回合；后台仍运行时不能把 Claude 描述成已完成。
   转录连续 6 分钟无更新且仍缺少完成通知时显示“结果待确认”，不推断失败或自动重试；之后收到权威通知仍可更新结果。
8. 上下文用量表示最近一次请求的窗口占用；带陈旧标记时不能解释成实时累计计费。
9. Codex `Response annotations` 用户消息中的有效 `<response-annotations>` JSON 转为回复引用，逐项展示所选文字和用户评论，`My request` 后的正文作为用户请求；协议说明、原始标签、内部 ID 和偏移量不进入气泡。原始消息仍保留用于模型上下文；非法或不完整包装保留原文，不猜测丢弃内容。
10. 聊天头部持续显示当前历史读取、同步、连接、等待回应和运行状态；状态使用 `role=status` 与 `aria-live=polite`，相同文本不重复播报。实时传输的“已同步”不能冒充执行 owner 已连接，断线反馈不得清空已读历史或输入内容。

## 2. 历史读取与实时同步

### 2.1 打开会话

1. 先读取保存历史的首屏并返回，原生连接和更多历史在后台加载。
2. 首屏优先展示最近内容，随后补齐较新的较大窗口；上翻接近顶部时再读取更早内容。
3. 保存历史与实时分页快照按首个重合轮次合并；完整实时快照是删除、回退等变化的最终权威。
   Codex CLI 的完整历史读取及完整恢复快照替换轮次和消息集合，清理原生已删除内容；增量事件和不含历史的元数据读取不得清空历史，迟到读取不得覆盖读取期间的新事件。
4. 切换聊天时作废旧页面请求和事件连接，草稿、附件与 Skill 选择仍按主机和会话隔离保存。
5. 会话依赖延迟加载资源时，后发起的打开请求或离开聊天页的导航优先；较早请求在资源加载完成后不得覆盖用户刚选中的会话或重新打开聊天页。
6. 历史读取失败可重试；历史可读但 owner 未连接时保持未连接提示，不伪报连接成功。Codex 打开页面不自动取得写锁；标题与详情显示所选执行方，重新连接和交接是独立操作。
7. 同一会话在没有新的回合定位目标时重复打开，应复用仍存活的时间线，不重复拉取或跳到底部；不同会话分别保存阅读锚点和是否跟随最新，返回时优先恢复锚点，锚点尚未加载时使用有限历史补页，不以错误内容下的数值 `scrollTop` 冒充恢复。
8. 显式 Run/回合定位、编辑或分支后的刷新、只读升级、会话已失效、团队身份变化或离开聊天页后迟到的打开请求优先于“同会话复用”，不得因复用跳过新目标或恢复旧页面。

### 2.2 增量更新

- Codex patches 仅在 `baseRevision` 匹配时应用，失配重新订阅完整快照，不在错误基线上局部修补。
- 所有 Agent 的规范化视图进入统一时间线投影，使用 epoch、sequence、消息版本和游标传输增量。
- 局域网使用 SSE；隧道等入口使用有登录校验的长轮询。SSE 断线带游标重连，不自动改成轮询。
- 过期游标、网关重启或快照代次变化触发重新同步，旧连接不得覆盖新页面的数据。
- delta 版本失配时共享恢复读取，但必须记录恢复期间后续失配帧的最高游标；响应未覆盖这些帧时从最新已应用游标继续读取，不能把已投递的新正文丢弃。切换页面或重置快照后停止旧代次恢复。
- 单页同时受条数和字节限制；正文被截断时提供继续读取，不能把预览当成完整内容。

### 2.3 下载离线历史

1. iOS 已配对电脑的菜单提供“保存当前聊天供离线阅读”。先打开本机 Codex 聊天；未加载、其他 Agent、远端 SSH 和未配对入口显示相应限制。
2. 网关只读打开已保存转录，从开头取至最近一条可确认的成功结束标记。下载期间新增的消息不进入这次快照，运行中的回合不进入离线副本。无法确认来源或完整边界时拒绝生成，不用前端窗口冒充完整历史。
3. 副本包含时间线可读正文与过程文本（含正常化后的命令及输出），标明保存时间和截止回合。附件字节、在线工具、审批和发送不进入离线副本。
4. 源转录超过 16 MiB、快照超过 8 MiB 或 4,000 行、单行超过 512 KiB 时明确拒绝，保留上一份已下载副本。下载不 Attach Agent 或改变未读、权限和执行归属。

## 3. 发送、补充与持久队列

### 3.1 每条消息的步骤

1. 客户端生成提交 ID，正文、附件、模式和目标会话共同构成请求身份。
2. 网关先写发送账本，再尝试派发；同 ID 同内容重试返回已记录结果，同 ID 不同内容拒绝。
3. 已确认接受显示为已接受；可证明未到达的失败才允许有界重排队。
4. 请求可能已经到达但确认丢失时标记“结果待确认”，不自动重发，由用户检查聊天后决定。
5. 确定性拒绝进入失败并保留草稿；人工重新发送必须沿用原请求身份以避免重复。
6. Codex 发送前只连接该聊天选定的执行方；连接故障不得静默切换到另一运行时。交接本身不重试失败消息，用户确认交接完成后再按原提交 ID 重试。

### 3.2 发送方式与队列

- **直接发送**：空闲时启动新回合；运行中按 Agent 能力补充当前任务或拒绝该方式。
- **完成后发送**：进入持久 FIFO 队列，当前回合落定后由维护循环或结算钩子派发，不代表点击时已送达。
- **补充当前任务**：仅对具备 steer 能力的运行中会话开放；能力缺失时回退排队或普通发送规则。
- 排队项可编辑、删除、重排和立即发送；编辑重置其失败重试阶梯，目标/计划激活消息不当作普通排队正文编辑。
- 立即发送运行中选中的排队项时，先停止当前回合再认领派发，防止结算钩子同时发送下一条。
- 前面存在结果未知条目时，后续条目不得越过它自动派发。
- 队列与草稿按会话和主机隔离；发送失败不得清空用户后来新输入的草稿。
- 草稿在当前浏览器 `localStorage` 持久化，键包含网关实例、主机和会话；记录正文、光标、工作模式、Skill 与单调 revision。旧 `sessionStorage` 文本和 Skill 仅在首次读取时迁移，不以失效附件或本地文件句柄冒充可恢复内容。
- 发送时记录草稿 revision；只有服务端确认接受且已保存 revision 仍相同才清除持久草稿。用户后来继续输入、切换光标或修改 Skill 都会阻止旧提交清掉新状态；存储不可用不改变发送结果。显式退出登录清理本网关草稿，普通断线或认证过期不清理。

## 4. 编辑、分支、审批与命令

### 4.1 编辑与分支

- Codex 最近用户消息可原生编辑并重新生成；更早消息或已完成回答可原生分支，原会话保留。
- ACP 的编辑与分支由网关合成新会话并注入截至指定位置的转录，不宣称 Agent 原生支持 rewind。
- 创建分支本身不主动执行新任务；来源关系持久保存，可从详情返回源会话。
- 编辑、分支和迁移都不会撤销文件修改；新旧会话共享目录时必须提示这一边界。
- 分支创建结果不明时先刷新列表核实，不能重复创建；已创建但连接失败时保留编辑草稿。

### 4.2 审批与命令

- 审批回应绑定仍存在的请求身份和允许选项；过期、不支持或非法回应保留卡片或明确失败，不转发任意 RPC。
- 审批区域按请求 ID 复用 DOM 卡片；请求内容未变化时，其他请求到达、离开或风险排序变化不得清空当前输入、选区或焦点。请求内容或界面语言变化时只重建对应卡片；移除和替换计划审批时执行既有销毁钩子，避免批注监听泄漏。
- 运行中的异步问题通过补充当前任务回答；已结束时在同一聊天启动回答后续回合。
- `/new`、原生/网关压缩和迁移各有独立入口与约束；未识别的斜杠文本仍按普通消息发送。
- 选区评论只把同一消息内的选区转成 Markdown 引用，不生成隐藏模型指令。

## 5. 附件、产物与文件安全

1. 上传按会话和主机隔离；单文件、单条数量和总大小均有限制，上传本身不启动模型任务。
2. 图片按内容识别为原生图片输入，其他文件以受支持的路径或资源块提供；能否读取仍取决于 Agent 能力和会话权限。
3. 发送、排队、补充和重试共享同一附件身份；发送失败保留草稿与附件。
4. 本地上传按保留期清理：上传超过 7 天，且未被同一会话内任何已发送、排队、结果未知或失败（可重试）的提交记录引用时，由后台每分钟一轮的清理删除其文件与元数据。单次清理失败只记日志，不影响其他上传、会话和发送；元数据无法读取的上传保持不动。已被清理的附件再次被引用时按「附件已不可用，请重新上传」处理。远端副本不承诺同样清理策略；Agent 内联图片不在此清理范围。
5. Agent 内联图片在网关数据目录按会话隔离、按内容去重，巨大编码和原始本地路径不进入网页消息正文。
6. 文件与图片下载仅允许当前聊天工作目录及明确许可的产物范围，并校验真实路径、类型和大小；目录外路径只显示描述或按受信事件规则处理。
7. “要求 Agent 附上产物路径”是发送约定，不是文件已生成的证明；文件服务仍需独立验证存在性与权限。

## 6. 异常与验收

| 异常 | 必须反馈与恢复 |
| --- | --- |
| 历史分页失败 | 保留已读内容并提供重试，不清空聊天 |
| 实时游标过期 | 全量或最近窗口重同步，旧帧不能覆盖新帧 |
| 发送确认丢失 | 显示结果待确认，不自动重发 |
| 审批已过期或答案非法 | 不转发，保留可重答状态或明确失效 |
| 分支已创建但连接失败 | 保留目标 ID 与草稿，刷新后复用目标 |
| 附件上传失败 | 单项可重试或移除，不影响其他附件和正文草稿 |

验收至少覆盖：

- [ ] 长聊天首屏、补页、完整正文和滚动锚定正确。
- [ ] 同会话重复打开不重建时间线；切换会话后恢复各自阅读锚点，显式回合定位仍优先。
- [ ] 草稿跨页面重载保留正文、光标、模式和 Skill；发送后新编辑不被旧 revision 清除，退出登录会清理。
- [ ] 新增、移除或重排审批不清空其他卡片输入；内容或语言变化只重建对应卡片。
- [ ] 团队画布等延迟资源加载期间连续打开不同会话或返回列表，最终只显示最近一次选择的页面。
- [ ] 增量恢复期间后续帧不会丢失；恢复响应较旧、快照重置和切换页面均不回退游标。
- [ ] Codex CLI 完整历史删除旧轮次及消息，同时保留读取期间的新事件和元数据读取前的历史。
- [ ] 后台任务通知不以原始 `<notification>` 标签或用户气泡出现，且不进入跳转列表、不提供编辑分支。
- [ ] Claude Bash 后台启动后立即显示进行中状态；完成通知按任务 ID 更新同一记录，成功/失败/未知有正确区分，关闭“执行过程”后仍可见，且通知不成为用户消息或新回合。
- [ ] 回复批注显示引用和用户请求，隐藏协议包装；多条批注、用户评论及非法/不完整消息有明确回退。
- [ ] 直接发送、steer、FIFO 队列、立即发送和队列编辑无重复派发。
- [ ] 同提交 ID 重放幂等，异内容拒绝，unknown 不自动重试。
- [ ] Codex 执行方与连接状态分别显示；交接失败保留历史和草稿，交接操作不发送或重放消息。
- [ ] Codex 原生编辑/分支与 ACP 合成行为不混淆。
- [ ] 审批重复回应、过期回应和异步问题不会串会话。
- [ ] 附件数量/大小、路径越界、保留期清理和远端副本规则符合本文。
- [ ] 迁移和压缩产生的网关提示不进入后续模型转录，详见[迁移与压缩基准](../session-migration-and-gateway-compaction.md)。

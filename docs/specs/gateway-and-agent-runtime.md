# 网关、会话与 Agent 运行时

状态：现行特性基准。

## 1. 范围与核心边界

本文定义网关如何发现会话、连接原 Agent、创建项目聊天，以及向客户端提供模型和运行时能力。

1. 网关不是新的模型执行器；实际任务由 Codex App、网关专用 Codex CLI app-server、ACP Agent 或 Agent Host 持有。
2. Codex 已有记录只读发现，运行控制绑定原生 owner；ACP 按会话归属路由，不靠 ID 前缀猜测 Agent。
3. 手机看到的历史可读，不代表目标已经可写；发送和审批必须等运行时连接就绪。
4. 创建空聊天不调用模型，也不复制另一条聊天临时修改的模型设置。
5. 原生 IPC 和 Agent 方言可能随上游版本变化，能力以运行时证据为准，不能把静态声明当成已验证支持。
6. 网关不擅自迁移因 provider、权限或配置缺失而无法恢复的原会话。

## 2. 会话发现、项目与新建

### 2.1 发现与项目列表

1. Codex 通过只读 SQLite 和保存历史发现本机及 SSH 会话；数据库并发变化时放弃不可靠副本并重试，不写原数据库。
2. ACP 通过 `session/list`、原生只读来源和新建占位补齐列表，按稳定会话 ID 建立归属。
3. 后台定时发现把新增、标题和项目变化折叠成单调列表版本；无客户端观看时暂停无用轮询。
4. 项目键包含主机身份，同名目录和同名项目不得跨主机合并；显式项目归属优先于路径前缀推断。
5. “移除项目”只隐藏新建入口，不删除磁盘目录、历史会话或团队。
6. SSH 列表复用桌面 App 已保存的连接和项目，只读取已保存且有关联项目或会话的 SSH 别名；远端列表在列表请求时读取并短暂缓存，后台定时发现不跨 SSH。远端不可达、别名无效或远端缺少 Python 时只把该主机列入不可用主机并说明原因，本机列表与其他主机仍可用；失败的主机在短时间内沿用上次原因，不在每次列表请求时重复连接。

### 2.2 新建聊天的逐步行为

| 步骤 | 网关行为 | 可见结果 |
| --- | --- | --- |
| 选择项目 | 重新解析已保存项目；自定义绝对路径仅允许本机现有目录 | 主机和目录确定，不能由客户端指定任意程序或运行时配置 |
| 提交创建 | 校验请求 UUID，并在创建账本中认领 | 同一请求重试复用结果，不同内容不得复用同一标识 |
| 创建空会话 | 安全条件下直接创建记录；复杂或无法可靠解析的配置回退官方运行时 | 不提交模型任务；失败不会留下伪造成功记录 |
| 确定执行方 | 网页新建 Codex 默认写入网关 CLI 执行归属，不自动打开桌面 App；显式选择桌面时才打开 App | 创建、连接和开始执行分别反馈；创建本身不启动任务 |
| 完成 | 持久化目标 ID 并刷新列表 | 手机可打开空会话；连接就绪后才能发送和审批 |

本机 Git 项目可选独立 worktree；`fresh` 与 `head` 的基线不同，必须在界面明确选择，不静默包含未提交改动。

SSH 远程项目目前只用于展示与分组：在手机端于 SSH 项目中新建聊天会被拒绝并说明原因，不会在本机目录创建。

网关专用 Codex CLI 当前依赖 Unix socket。Windows 保留桌面创建与执行，不展示交给 CLI 的入口；显式请求不支持的执行方在创建前拒绝。迁移/网关压缩新建的 Codex 目标采用同样默认规则，源会话归属不变。

## 3. Codex 与 ACP 控制流程

### 3.1 Codex

1. 每条聊天只有一个选择的执行方：桌面 App 或网关专用 CLI。未记录归属的已有聊天保持桌面路径；已有 CLI 账本继续有效。归属持久化，但不代表已取得原生写锁。
2. App 路径通过桌面 IPC 订阅快照，匹配 `hostId + conversationId + ownerClientId`；CLI 路径连接独立的官方 app-server。两条路径保留同一聊天 ID、目录和 provider，不互相静默回退。
3. 打开聊天只读历史与状态，不调用 CLI `thread/resume`，不自动接管或发送待处理消息。用户发送或点击重新连接时才尝试所选执行方；失败保留草稿并明确提示原因。
4. 发送、补充、停止、模型设置和审批始终使用所选运行时。界面区分执行方、实际连接/写入者和任务状态；共享历史不代表可并发写入同一聊天。
5. “交给网关执行”仅在历史已落定、没有待答审批、未派发消息或结果未知提交时尝试接管；原 App 的写锁仍在时拒绝，保持原归属，不删除锁或停止 App。
6. “交给桌面执行”先确认 CLI 聊天、后台终端与子代理均空闲并释放原生订阅，再持久化桌面归属并打开 App。释放或持久化失败时如实报错，不宣称交接成功；重试不得发送消息。
7. CLI 空闲释放写锁后仍保留执行归属；被动历史读取不重新抢锁。App 与专用 CLI 持有的任务不因网关重启而自动取消。
8. 桌面特有的浏览器、插件和其他能力按实际执行方门控，不能因共用 Codex 数据目录承诺继承。协议只开放明确操作，不提供任意 RPC 代理。

### 3.2 ACP 与 Agent Host

1. Manager 根据活跃句柄、列表缓存、别名和原生源解析会话归属，再执行 `session/load` 或原生只读跟随。
2. `session/prompt`、审批回应、设置、取消和可用扩展 RPC 统一映射到规范视图；不同 Agent 的方言差异不得泄漏成错误的全局假设。
3. 桌面同时持有会话时，可提供原生历史只读视图；“尝试接入”只在空闲且能获得写句柄时切换。
4. prompt 空闲超时与显式停止都进入取消流程；有待答审批时不把等待用户误判为 Agent 无响应。
5. 网关内 spawn 的 Agent 随网关退出而中断；Agent Host 持有的子进程在网关重启后继续运行，重连恢复视图。
6. Host 转发需保持请求 ID 和反向审批的会话归属，不能把多个网关连接的响应串线。

### 3.3 SSH 远端会话

1. 主机与项目来自桌面 App 保存的 SSH 连接和远程项目；手机不保存私钥，网关也不新增或修改这些连接。
2. 远端读取经已有 SSH 别名，以非交互、严格主机指纹检查、禁用转发的方式，把只读辅助脚本经标准输入交给远端 Python 执行，不在远端安装文件；远端需有 Python 3。
3. 辅助脚本只做两件事：执行网关生成的只读查询，读取远端 Codex 数据目录内的会话记录；越界路径拒绝。会话记录的解析、时间线投影与分页全部由本机网关完成，远端只返回原始数据；超大的会话记录只取最新部分，并标明更早的轮次未加载。
4. 远端会话以主机身份区分：项目键和分组键包含主机 ID，不与本机同名目录或其他主机合并。
5. 网关没有接入远端运行 owner 时，SSH 会话保持只读：列表与历史可读；发送、补充、停止、设置、审批回应、重命名、上传、迁移、排队、删除和新建均明确拒绝并说明原因，不伪报已接受；目录、权限和 Goal 控件不展示。
6. 只读页面不实时刷新，重新进入会话或刷新时重新读取；远端读取失败返回可重试的错误。

## 4. 模型、Skill、权限与能力门控

- Codex 运行时没有已登录账号时，模型目录读取仍可返回可读信息，但 Fast 不可用；`account/read` 返回空账号不得导致接口崩溃。
- 模型、推理强度和 Fast 设置只作用于当前会话，通常从下一轮生效；不操作 Fast 开关时不得顺带改变原速度档位。
- 模型目录和 Skill 目录来自对应主机的只读运行时，不得复用另一台主机的路径；未接入远端目录时不展示目录控件，也不得用本机目录代替。
- Codex Skill 以受信目录 ID 解析为原生引用，每条消息最多 8 个；支持斜杠命令的 ACP Agent 每条消息限选一个前导命令。
- 协作模式、权限预设和 Goal 是不同概念。只有明确暴露权限配置的 Agent 才显示权限切换，不能把 `mode` 一律当权限。
- 没有工作模式接口的 ACP Agent 仍允许普通发送和排队发送；普通模式不调用不存在的 `session/set_mode`。显式计划模式仍按真实能力校验。
- 权限与计划共用 `modes` 的 ACP Agent 在计划期间选择权限时，只记录当前连接会话的待生效选择，不退出计划；无论由网关、Agent 还是桌面退出计划，下一次普通发送前必须应用该选择，失败则阻止发送并返回错误。未选择新权限时保留 Agent 自己切换后的权限；独立权限配置仍即时应用。
- `steer`、`goals`、`skills`、分支、编辑、重命名和 Fast 均由运行时能力与会话状态共同门控；没有能力时前端隐藏、后端仍拒绝。
- 设置部分成功时必须返回可见的部分失败信息，不能把所有选项显示成已应用。
- 权限审批保留 Agent 提供的命令、目录、文件和网络上下文；自动预判只辅助决定，不扩大可批准选项。

## 5. 生命周期、异常与验收

| 场景 | 必须行为 |
| --- | --- |
| 历史可读、owner 不在线 | 允许阅读；写操作等待或提示接管，不直接报错成历史不存在 |
| owner 订阅返回不同基线 | 重新获取完整快照，禁止局部补丁覆盖新状态 |
| 创建超时或确认丢失 | 先查创建账本和聊天列表，不重复创建 |
| Agent 能力缺失 | 控件不可用且后端拒绝，不静默换成另一项设置 |
| 桌面独占 ACP 会话 | 原生历史只读；运行中不强抢写句柄 |
| 网关重启 | Codex/Host 任务继续；网关内 ACP 中断如实显示，不承诺自动续跑 |
| 上游 App 或协议升级 | 能力降级并报告不兼容，不用未经验证的方法猜测成功 |

验收至少覆盖：

- [ ] 本机、SSH、不同 Agent 的列表与深链归属正确，同名项目不串主机。
- [ ] 新建请求重试不重复，创建不调用模型，目标接管前不能误发送。
- [ ] 保存历史与实时快照可合并，patch 基线失配能完整恢复。
- [ ] 网页新建默认 CLI，不打开 App、不启动回合；已有桌面聊天发送失败不自动改归属。
- [ ] 打开/刷新聊天不恢复 CLI 写入者；显式交接保留 ID、目录和 provider，写锁冲突、忙碌、审批、结果未知与落盘失败均不误报成功。
- [ ] 执行归属重载后稳定，界面区分归属与实际连接；CLI 释放后可显式交给桌面。
- [ ] 模型、Skill、权限和 steer 均由真实能力门控。
- [ ] 无工作模式接口的 ACP Agent 可普通发送及排队；不支持的计划模式明确拒绝。
- [ ] 计划期间保存的权限在 Agent 自行退出后仍于下一次普通发送前生效，失败不启动新回合。
- [ ] Codex、网关内 ACP、Agent Host 三类进程重启行为符合本文。
- [ ] 只读桌面会话可阅读，空闲接入与运行中拒绝接入均有明确反馈。

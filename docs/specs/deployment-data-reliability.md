# 部署、数据与可靠性

状态：现行特性基准。

## 1. 部署与运行边界

1. 网关以单一 Go 二进制运行，网页资源通过 `go:embed` 打包；修改前端或后端后都需要重新构建并由用户重启网关。
2. macOS 可用 launchd 托管网关和 Agent Host；稳定签名身份用于减少重复目录授权，其他平台按各自启动脚本运行。
3. 网关参数仅开放明确的数据目录、端口、Codex home、IPC 和运行时入口；网络配置不通过公网 API 任意修改。
4. NAS/Docker 只承担 HTTPS 入口，Codex App、网关专用 Codex CLI app-server、Agent 和网关仍在原电脑运行，不能仅部署容器就接管另一台电脑。
   Codex 专用 CLI 使用网关数据目录下的独立 socket，网关退出只断开连接；执行归属保存在网关账本中，重启后恢复路由而不抢占会话。历史共享不扩大写权限，测试运行时不得被误认为桌面或主网关运行时。
5. Quick Tunnel 依赖外部 `cloudflared`；下载脚本必须校验锁定版本与摘要，个人二进制和配置不进入仓库。
6. 部署后分别验证本机、局域网和实际外网入口；SSH 登录成功不等于转发和公网 HTTPS 已可用。
7. 网关重启由用户明确执行，自动化修改代码后不得自行重启正在使用的服务。
8. 网页源码继续以 `web/` 嵌入，不增加 Node 或前端框架运行要求。网关在装配静态资源时一次性压缩 JS/CSS，并以最终内容哈希生成生产 URL；源码文件、压缩结果和 HTML 引用必须来自同一次装配。
9. HTML 保持 `no-store`；原始静态地址保留兼容并支持 ETag 重新验证；内容哈希地址使用私有长期缓存和 `immutable`。静态资源压缩、缓存和 304 不改变现有登录、Host/Origin、CSP、Content-Type 与 gzip 行为。
10. 静态资源读取或压缩失败必须显式返回错误，不能静默混用不同版本或把损坏页面当成发布成功。回归必须检查实际嵌入 FS 的 HTML 引用和压缩后资源，而不只检查源码文件存在。
11. 首屏只立即加载登录、聊天列表和共用交互所需脚本。账号面板在点击“账号与接入”时加载并初始化；Markdown/KaTeX 与 Diff 在打开聊天前加载；Dagre 和团队画布在打开团队会话时加载，团队 Lead 的普通聊天深链也必须经过同一初始化路径；Swarm 在进入 Run 详情时加载。图布局未就绪时保留既有分层列表回退。团队模型和列表所需脚本仍随首屏加载，不能为拆包改变聊天分组、团队入口或深链行为。
12. 延迟加载由统一加载器去重并遵守组内依赖顺序。生产 HTML 通过非执行 JSON 清单提供原始地址到哈希地址的映射，动态请求同样使用压缩和长期缓存；直接访问旧地址仍保持兼容。任一资源失败只清除失败项的加载状态，已成功资源继续复用，再次进入对应入口可重试。
13. 账号资源失败时不打开半初始化面板，并提示再次点击重试；Markdown/Diff 或团队画布资源失败时保留当前聊天并提示重新打开目标会话重试；图布局资源失败时使用列表并提示下次进入视图重试；Swarm 资源失败时保留其余 Run 详情，重新进入 Run 可重试。延迟加载不得自动重放消息、审批、账号切换或其他写操作。
14. TypeScript 只作为开发期静态检查，通过锁定的 npm 开发依赖运行；全部自有 JS 做解析检查，新模块及已完成类型收敛的文件用 `@ts-check` 逐步启用 `checkJs` 语义检查，不能用批量 `@ts-nocheck` 或无意义忽略伪造全量覆盖。网页源码、Go 构建和网关运行不依赖 Node、TypeScript 或前端框架。标准前端门禁同时覆盖脚本解析、已纳入文件的静态检查与既有 Node 行为测试。

## 2. 数据目录与事实来源

默认 `.local/` 保存网关自有状态，Agent 原生历史仍留在各自数据目录。

| 数据 | 职责与恢复口径 |
| --- | --- |
| `config.json`、`desktop.json` | 登录、监听和连接配置；敏感秘密不放入普通响应 |
| `submissions.json`、按主机分目录的同名文件 | 消息正文、提交去重、队列与派发结果；是发送恢复的重要依据 |
| `creations.json` | 新建、团队成员、迁移目标的创建占用与源会话提示 |
| `goal-commands.json`、`acp-goals.json` | 原生 Goal 操作与托管 Goal 两套独立状态，不可互相替代 |
| `acp-plans.json` | ACP 计划按 Agent、会话和计划 ID 保存的辅助修订历史；保留最新 100 版且每计划正文合计最多 8 MiB，不是审批或幂等事实来源 |
| `forks.json`、`hidden-projects.json` | 分支来源和项目入口显示状态 |
| `team-journal.jsonl`、团队快照与输入账本 | 团队事实、可重建投影、输入路由与修订 |
| `auth-sessions.json`、审批与通知账本 | 登录、外部回应幂等和通知对账 |
| `pool/`、`jev.json`、上传目录 | 账号快照、评估配置和会话附件，使用受限权限 |

发送、创建和 Goal 等关键幂等账本损坏或不可读时，网关必须拒绝启动，避免丢失去重信息后重复执行；不得把关键账本静默当成空文件。可重建快照与不可重建事实必须区别处理。

## 3. 幂等、结果未知与恢复

### 3.1 外部副作用的统一分类

| 结果 | 含义 | 自动行为 |
| --- | --- | --- |
| accepted | 已确认目标接受 | 记录结果，重放返回原结果 |
| rejected / failed | 可证明未接受或明确拒绝 | 保留错误；仅安全场景有界重试 |
| outcome unknown | 请求可能已到达，确认丢失或证据不足 | 不自动重放，要求核实或人工恢复 |

1. 消息使用提交 ID，创建/迁移使用请求 UUID，Goal 使用操作 ID 与修订号，团队操作另带期望版本。
2. 同身份同内容重试复用原结果，同身份异内容拒绝；跨链路写请求不自动重放。
3. 只有可证明未到达的失败才允许重新排队，并有次数上限；结果未知不能被维护循环“修复”为再次发送。
4. 重启按事实账本、目标状态和会话证据对账；不能仅根据当前内存或最新快照推断旧请求一定失败。
5. 关键状态先持久化再执行外部副作用；完成状态落盘失败时接口必须报告，而不是假装已经可靠完成。
6. 新持久字段必须覆盖加载、原子保存、克隆、事件重放和兼容旧记录，避免重启后字段消失。

## 4. 安全、隐私与资源限制

- HTTP 使用登录、Host/Origin、CSRF 和受限文件路由；不能把 Agent RPC 或本机控制接口直接暴露成通用代理。
- 文件访问校验解析后的真实路径、允许目录和大小；上传、正文、时间线、日志和评测输出均有有界预算。
- 密码、令牌、API Key、账号快照、通知密钥和本地控制令牌不得进入普通 API 响应、公开事件或仓库。
- 历史数据库和原生记录默认只读；只有明确的新建或官方操作路径可以写入，发现过程不得修改原聊天。
- SSH 远端读取只使用只读连接和只读查询，不向远端写入文件或安装程序；SSH 参数固定为非交互、严格主机指纹检查、禁用转发，别名来自桌面 App 已保存的连接。
- 团队验证命令使用固定 argv 而非任意 shell；本地快照不是 OS 沙箱，不满足安全条件时拒绝执行。
- 通知、额度、Jev 和隧道都是外部网络副作用，配置、隐私和失败语义必须独立，不得因一个通道失败回滚本地业务事实。
- 工作区删除、原生会话删除、账号切换和网关重启属于不同风险等级，不能混用确认与恢复策略。

## 5. 验证、发布与运维

### 5.1 标准验证

```sh
make test
npm ci
make check-web
make check
make conformance
```

按改动范围选择必要门禁：Go 全量测试、前端测试、竞态、HTTP golden、真实运行时隔离验证和真机验收。导入成功或编译通过不能替代真实操作链路。

### 5.2 发布与运维

1. 确认工作区改动范围，不把无关文件、个人配置、测试产物或秘密纳入提交。
2. 文档先行并回写实现偏差；用户可见行为变化同时更新对应基准与验证记录。
3. 构建目标产物并核对运行入口；前端变更也需要重新打包网关。
4. 由用户决定并执行重启，随后验证实际访问入口和核心写操作。
5. 排错优先查看网关、Agent Host、隧道和通知各自日志，区分代码失败、依赖未就绪和上游协议不兼容。
6. 回滚代码时同时考虑账本兼容；不能通过删除关键账本制造“干净启动”，否则会失去幂等保护。

## 6. 验收标准与参考

- [ ] 关键账本损坏会阻断启动，可重建快照能从事实来源恢复。
- [ ] 消息、创建、审批、Goal、团队操作的重试和未知结果均不会重复执行。
- [ ] 重启、断连和跨链路切换保留正确的草稿、队列、修订与审计状态。
- [ ] 文件越界、超大输入、固定命令和私有字段均有明确拒绝或有界处理。
- [ ] 测试覆盖真实交付形态，未实机验证的平台和上游能力明确标注。
- [ ] 部署后由用户重启并验证实际网关，不自行中断在线服务。

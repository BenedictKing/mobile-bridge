# 账号、接入与额度管理

状态：现行特性基准。

## 1. 账号体系与数据边界

网关登录、Codex 接入和 ACP Agent 账号是三套独立身份，不要求手机保存模型凭据。

1. 网关账号只保护 HTTP 访问，不代表任何模型提供商身份。
2. Codex 官方账号、自定义 API provider 和桌面 profiles 由本机运行时与接入面板管理。
3. ACP 账号池按 Agent 分池保存本机快照，支持 Kimi、ZCode、MiniMax 和 WorkBuddy；Codex 在统一视图中只读，不使用 ACP 切换器。
4. 凭据、令牌和加密快照只在电脑本地使用，普通 API 响应不得返回秘密；池目录和文件使用受限权限。
5. 删除池中快照不等于退出官方当前账号；重新登录原位替换只影响指定账号，不改变其他槽位。
6. 额度是特定账号和时间窗口的快照，不是团队所有成员共享的统一余额，也不是 token 计费总账。

## 2. Codex 接入切换

### 2.1 主流程

1. 用户在电脑端添加、导入或修改官方账号、自定义 API 与 profiles；手机端选择已保存接入。
2. 切换前读取当前接入和桌面状态，验证目标配置，保留回滚所需信息。
3. 退出官方桌面，替换本机认证及默认 provider，再启动并核验目标接入。
4. 任一核验失败按原状态回滚并报告；网关自身保持运行。
5. 成功后新聊天使用新默认接入；已有聊天的 provider、权限和审批策略不被静默改写。

### 2.2 额度与重置卡

- 官方账号可显示剩余额度、恢复时间和重置卡；数据缺失时显示暂未提供，不伪造百分比。
- API 或第三方 provider 不显示官方账号专属操作。
- 重置卡逐次确认并沿用原消费请求标识，中断后重试不得重复核销。
- 账号额度属于本机当前 Codex 账号，不随 SSH 会话切换到远端账号。

详细凭据扫描、回滚与恢复约束见[账号与接入](../account-switching.md)。

## 3. ACP 账号池主流程

1. 用户通过设备授权、扫码、OAuth 或捕获本机当前登录添加账号；后完成的旧登录流程不得覆盖新流程。
2. 池按账号保存凭据快照和额度窗口；当前槽位按周期刷新，备用账号通过低频全量清扫补充，不做全池高频请求。
3. 面板展示各窗口已用、剩余和重置时间，支持手动切换、重登和删除快照；重新登录失败的账号标记需要认证。
4. 切换前检查活跃回合、待答审批、槽位漂移和目标登录态，保存旧槽位后原子替换。
5. 替换后重挂存活会话并核验账号指纹；失败回滚并反向恢复，所有尝试写审计历史。
6. ZCode、MiniMax、WorkBuddy 的槽位结构、桌面退出和凭据格式不同，必须走各自切换器，不能用一个文件复制流程通用化。

ZCode 可优先使用官方重置卡原地恢复；无卡、恢复失败或不适合使用时才进入账号切换。辅助额度窗口不参与主 AI 额度耗尽判断。

ZCode 计费额度查询必须读取本机 `v2/telemetry-state.json` 的 `deviceMid`，并通过 `X-Device-Mid` 请求头发送；设备标识只在本机读取，不进入账号快照或普通 API 响应。缺少该请求头导致的 `HTTP 400 / code 3001` 属于额度查询失败，不得标记为 Token 失效；BigModel 监控备用查询不发送此 ZCode 专用请求头。

## 4. 自动切换与续跑

### 4.1 触发与决策

- 回合结束后的疑似额度错误先经规则初筛，再实时刷新额度复确认，避免瞬时 429 误切。
- 轮询越过阈值走同一决策路径；距自然重置很近时优先等待，不浪费切换或重置卡。
- 冷却时间、单位时间切换次数、连续切走弃用等门控从持久审计历史计算，重启不能清零。
- 目标选择以主窗口剩余量为核心，并考虑最久未用；认证失效、冷却或不安全账号不得作为候选。
- WorkBuddy 等桌面与 CLI 并行场景采用保守门控，无法安全替换时只通知，不强行切换。

### 4.2 切换后的恢复

1. 切换成功后重新附接受影响会话并核验新账号。
2. 对被额度问题打断的会话重新评估停止原因；只有适合续跑时才发送恢复提示。
3. 切换续跑使用独立上限，不占普通自动继续预算；人工操作同时重置两类计数。
4. 会话血缘确定损坏时不回滚到耗尽账号，旧会话明确报错，不能无限重试。
5. 自动切换可全局或按池关闭；关闭后仍可查看额度与手动切换。

## 5. 团队额度投影与安全门控

1. 团队额度接口按成员 Agent 提供当前账号的本地快照，状态区分可用、无活动账号、不支持和暂不可用。
2. 各窗口统一投影已用、限额、剩余、剩余百分比和重置时间；辅助额度剔除，不触发远端刷新。
3. 主控派发简报可包含不含账号标识的额度摘要，帮助选择成员；摘要进入输入哈希，变化后不能复用旧缓存冒充新事实。
4. 额度不足只作为调度和恢复证据，不能自动改写团队成员或绕过用户指定的账号安全门控。
5. 活跃回合、待答审批、桌面与 CLI 并行、血缘损坏等情况分别处理，不能为追求可用性强行切换。

## 6. 异常、持久化与验收

| 场景 | 必须行为 |
| --- | --- |
| 额度接口失败或数据陈旧 | 标明不可用或快照时间，不伪造实时余额 |
| 目标登录态无效 | 不关闭当前桌面、不改当前槽位 |
| 切换后核验失败 | 回滚槽位并恢复会话，记录审计 |
| 旧登录流程迟到完成 | 丢弃，不覆盖新登录或新账号 |
| 网关重启 | 保留池、设置、冷却和审计历史，不重置自动切换门控 |
| 凭据损坏或需要重登 | 标记 reauth，不把它当作有可用额度账号 |

验收至少覆盖：

- [ ] Codex 接入切换失败可回滚，已有会话 provider 不被静默改写。
- [ ] 四类 ACP 池的添加、重登、捕获、删除和手动切换互不串号。
- [ ] 当前槽位与备用账号轮询频率分离，辅助额度不触发切换。
- [ ] 冷却、次数限制、自然重置宽限和 ZCode 重置卡顺序正确。
- [ ] 切换续跑与普通自动继续预算独立，重启后审计门控仍有效。
- [ ] 团队额度快照不泄露账号身份、不触发远端刷新。

# 连接、客户端与通知

状态：现行特性基准。

## 1. 认证与访问安全

1. 网关登录独立于模型账号，使用密码摘要和 HttpOnly Cookie；HTTPS 入口增加 Secure 属性。
2. Host、Origin 和跨站请求校验覆盖 API、事件流和附件；写操作另需 CSRF，预认证接口只保留明确豁免。
3. 普通登录按配置时长到期且访问不续期；“记住密码”使用独立的固定期限；网关不设到期不代表浏览器永不清 Cookie。
4. 同一来源 IP 连续失败触发封禁并持久化；可信代理必须显式配置，否则不能信任转发头。
5. 登录记录代表浏览器会话，不是硬件身份；多设备共享出口 IP 时会共享封禁影响。
6. 免密模式仍需建立会话与 CSRF，但任何能访问者都能读取和控制聊天，只能用于受控网络。
7. 修改凭据、退出登录和链路切换要撤销或隔离相应会话，不能把 Cookie 放宽到父域共享。

## 2. 网络入口与实时传输

| 入口 | 主要用途 | 关键约束 |
| --- | --- | --- |
| 局域网 HTTP | 同网或可信热点 | 可按网卡绑定；动态地址与静态绑定行为不同 |
| 临时 Cloudflare HTTPS | 无域名的临时外网 | 地址会变化，隧道进程与 cloudflared 必须可用 |
| Cloudflare 固定隧道 | 有域名、无公网服务器 | Token 只运行已有隧道，不自动创建 DNS |
| 自有服务器 SSH 回程 | NAT 后通过自有域名访问 | 严格指纹、回环转发、保活和失败退避 |
| NAS / 已有反代 | 复用已有 HTTPS 入口 | 只部署入口，原电脑和网关仍须运行 |

- 多入口共享同一业务与认证实例，可独立启停；关闭局域网不影响已配置的外网入口。
- 局域网默认使用增量 SSE；不支持 SSE 的隧道使用增量长轮询，传输方式由认证信息宣告。
- SSE 断线带游标退避重连，不回退轮询；代次和游标防止旧事件覆盖新页面。
- 固定入口检测核对非秘密实例 ID，不携带登录凭据、不跟随重定向。
- mDNS 广播默认关闭，显式开启后广播失败也不能影响已有 HTTP 服务。

## 3. 局域网直连与 SSH 边界

### 3.1 公网页面使用局域网直连

1. 公网页面保持原地址，通过已登录同源请求和 CSRF 获取短期单次 grant。
2. 直连 origin 交换独立会话前，必须证明它属于同一个网关实例。
3. 只有 GET、HEAD 和实时游标等安全读取可切到直连；公网与直连 Cookie 各自隔离。
4. 直连失效、认证失败或资源加载失败时回到公网并按退避重新探测。
5. POST、PATCH、DELETE 中断后不跨链路自动重放；恢复后的同源页面仍执行 CSRF 和请求幂等。

### 3.2 两类 SSH 不得混淆

- Codex/ACP 的 SSH 会话复用桌面已经保存的主机、项目和连接，操作继续在原服务器执行，手机不保存私钥。
- 自有服务器入口的 SSH 只负责公网回程转发，严格主机指纹、非交互认证和回环绑定，不用于登录远端执行聊天脚本。
- 远端文件、模型、Skill 和附件路径属于对应主机，不能映射成本机路径。
- 远端主机不可达时显示局部错误，本机和其他主机继续可用；MFA、跳板等未支持能力明确列为限制。

## 4. Web、Android 与 iOS

### 4.1 共享 Web

- 原生 HTML/CSS/JavaScript，无前端构建步骤和外部 CDN 依赖；语言、显示偏好和草稿按浏览器保存。
- 支持 Markdown、代码、公式、长文分段、图片预览、文件下载和移动端布局；没有离线聊天 Service Worker。
- 界面翻译只覆盖 UI 文案，聊天原文、模型/Skill 描述、命令和日志不自动翻译。

### 4.2 原生容器

- Android 通过 NSD 和历史 origin 竞速发现可信网关，先匿名证明再引导路由凭据；公网失败可恢复 LAN shell。
- iOS 通过 NWBrowser、多电脑 Keychain、既有信道切换、下载和 Live Activity 复用同一 Web 业务。
- 原生恢复同样禁止写请求跨链路重放；派生路由 Cookie 必须是 HostOnly，不与公网共享。
- 推送、后台同步和下载受系统版本、电池和网络策略影响；构建通过不等于真机端到端已验证。
- 各平台真实验证范围以 [VERIFICATION.md](../../VERIFICATION.md)、[Android](../android.md) 和 [iOS](../ios.md) 为准，不得把未验收能力写成已实测。

## 5. 通知、未读与活动状态

### 5.1 通知主流程

1. 远程推送由用户先配置 Bark、ntfy 或原生推送通道，再设置全局和单会话策略；通道与策略分别开关。本设备系统通知不依赖这些通道。
2. 新待处理请求、完成事件、团队 Run 状态和入口地址按各自规则产生通知事实。
3. 每个通道独立投递、退避和记录结果，一个通道失败不影响另一个，也不回滚会话或 Run。
4. 重试前重新核对请求是否仍待处理、聊天通知是否仍开启；已失效事件不继续推送。
5. 对账只补发已经产生但未确认的记录，不为新通道或新接收目标重放全部历史。
6. 完成通知以首次实时连接为边界，之前已经结束的历史不补发；网络异常不承诺严格恰好一次。
7. 通知跳转优先使用显式地址，再选固定 HTTPS、临时入口或 LAN；通知不包含登录令牌。

### 5.2 本设备系统通知

1. 用户可在外观设置的“通知与结果”中独立开启本设备系统通知，无需配置 Bark、ntfy 或原生推送；新待确认请求与轮次结束沿用全局及单会话的有效通知策略。
2. 网页或 Android App 进程保持运行时继续轮询活动状态，只在页面进入后台后提醒；正在查看的会话不提醒。首次轮询只建立基线，不补发已有请求或历史终态，同一请求阶段和同一轮次终态不重复提醒。
3. 浏览器仅在 HTTPS 或 localhost 且提供 Notification API 时可用；不支持的环境禁用开关并说明原因。不增加离线 Service Worker，页面或 App 关闭后不承诺本设备通知，也不承诺系统后台冻结期间持续轮询。
4. Android 通过原生桥弹系统通知；Android 13 及以上需运行时通知权限，旧版 APK 显示不支持。通知绑定产生它的已保存网关配置，点击时先恢复该网关再打开对应会话；冷启动未登录时保留网关和会话目标，登录后再跳转。来源网关配置已删除时不得在当前其他网关误打开同 ID 会话。
5. 本设备通知与 Bark、ntfy 等远程通道独立投递，不互相确认展示结果；同时开启时可能分别提醒。关闭本设备通知停止后续提醒，并清除 Android 已展示的本应用通知。

### 5.3 未读与活动

- 会话活动以持久终态轮次标识记录正常完成、失败/停止和断线状态；进入聊天清除待查看标识。
- 首次使用不把所有历史标为未读；仅阅读不伪造新的最近交互。
- 运行标识、推送通知和通知策略是不同层面，关闭网页不会取消任务。
- 团队通知以独立运行账本记录水位，状态落账后才发布，不因通知失败修改 Run。

## 6. 异常与验收

| 场景 | 必须行为 |
| --- | --- |
| 公网与 LAN 切换时写请求中断 | 结果按未知处理，不在另一链路自动重放 |
| SSE 断线 | 使用原游标重连，不切换到不同传输语义 |
| 固定入口指向其他服务 | 实例 ID 不一致，检测失败且不携带凭据 |
| 通道接受但手机未收到 | 显示投递事实边界，继续按通道对账，不宣称系统通知已展示 |
| 首次连接前已有完成历史 | 不补发完成通知 |
| Android 通知后切换了当前网关 | 点击通知恢复来源网关后再打开会话；来源配置已删除则不跨网关跳转 |
| 原生 App 未做真机验收 | 文档明确未验证，不写成已支持全功能 |

验收至少覆盖登录/封禁重启恢复、CSRF 与 Origin、多入口实例检测、直连隔离、SSE/轮询游标、SSH 主机隔离、通知去重与关闭后停止重试，以及 Android/iOS 各自真实设备范围。

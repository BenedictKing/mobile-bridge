# 团队实时 Run 面板改造计划

状态：待评审；线框图见 [team-live-run-panel-wireframe.html](./team-live-run-panel-wireframe.html)。

## 1. 背景与目标

当前团队能力分散在三个位置：聊天内的 Workflow 摘要、独立 Run 详情、全局团队工作台。用户想知道“谁在做什么、为什么停住、哪项任务解锁下一步”时，必须离开聊天并重新建立上下文。

本计划只实施此前建议的前三项：

1. 在团队聊天旁增加当前 Run 的常驻面板。
2. 把静态成员标签升级为当前 Run 的实时成员名单。
3. 在现有 Dagre 任务图上增加成员、任务、上下游和详情的联动。

目标不是增加新的编排能力，而是缩短“发现状态 → 定位责任人 → 查看证据 → 返回继续沟通”的路径。

### 成功标准

- 活跃 Run 打开团队聊天后，用户不离开聊天即可看到总体进度、下一步和成员状态。
- 任一任务最多两次操作即可定位负责人会话或完整任务卡。
- 任一阻塞任务可直接回答“等待谁”和“完成后解锁什么”。
- 桌面与手机使用同一 Run、成员和图数据，不形成两套状态结论。
- 关闭面板只影响展示，不暂停、取消或改变 Run。

### 非目标

- 不实现运行前审批、团队归档、成员邮箱、未读消息或模型路由编辑。
- 不重写 Dagre 布局，不引入新的图库或工作流引擎。
- 不把全局 Dashboard 改成只显示当前会话；其多团队聚合能力保持不变。
- 不做可拖拽浮窗、职业插画和装饰性动画。
- 不根据会话是否在线猜测成员状态；状态只来自当前 Run 的任务与成员投影。

## 2. 信息架构与关键流程

### 三级信息层级

```text
一级：聊天内 Workflow 摘要
  当前结论 / 任务进度 / 最近回音 / 下一步 / 展开实时面板
                 ↓
二级：聊天旁实时 Run 面板
  Run 头部 / 下一步 / 实时成员 / 任务关系图 / 选中项解释
                 ↓
三级：完整 Run 详情
  阶段图 / 完整任务卡 / 结果证据 / Diff / 统计 / 历史事件
```

一级保留现有 `TeamChatController`，不复制完整面板；二级新增共享视图；三级继续由 `TeamRunScreen` 承担。全局 Dashboard 仍是跨团队入口，不属于这三级的替代品。

### 桌面结构

```text
┌────────────┬──────────────────────────┬──────────────────────┐
│ 项目与会话 │ 团队主控聊天             │ 当前 Run       [收起] │
│            │ 用户消息                 │ 运行中 · 3/6 任务     │
│ 团队       │ Lead 回音                │ 下一步：等待前端实现  │
│ 成员会话   │ Workflow 摘要            ├──────────────────────┤
│            │                          │ 成员                 │
│            │                          │ 任务关系图           │
│            │                          │ 选中项：等待 / 解锁  │
│            │ 输入区                   │ 完整 Run ↗           │
└────────────┴──────────────────────────┴──────────────────────┘
```

### 手机结构

手机默认保留聊天全宽，底部显示一条“当前 Run · 状态 · 下一步”摘要栏。点击后打开非模态底部抽屉；抽屉内顺序为下一步、成员、分层任务列表、选中项解释。完整 Run 仍独占页面，返回后恢复原抽屉和选中项。

### 核心路径

1. 打开团队 → 复用当前 Run 选择规则 → 显示聊天摘要与实时面板。
2. 点击成员 → 高亮其任务 → 查看当前任务 → 显式点击“打开会话”。
3. 聚焦任务 → 临时预览上下游 → 点击固定 → 查看等待原因和下游解锁。
4. 点击“定位任务” → 打开完整 Run 并滚动到任务卡 → 返回原团队聊天。
5. 切换团队或普通会话 → 隐藏面板并取消图请求；返回团队后恢复该团队的展示偏好。

## 3. 第一项：常驻 Run 面板

### 内容顺序

1. **头部**：`当前 Run`、状态徽标、目标摘要、收起按钮。
2. **进度**：完成任务数/总任务数、最近回音时间；不使用只有百分比的假精确进度。
3. **下一步**：复用 `nextAction`；等待输入和失败时置于成员与图之前。
4. **成员**：实时名单，见第 4 节。
5. **任务关系**：复用 `/graph`，见第 5 节。
6. **选中项解释**：负责人、未满足前置、直接下游和可用动作。
7. **底部动作**：`打开完整 Run`；不重复暂停、恢复、转发等完整详情操作。

### 当前 Run 选择

直接复用 `TeamChatController.refreshRun()` 的规则：优先最近未结束 Run，否则最近终态 Run；`excludedRuns` 同样生效。面板不得另行按 `updatedAt` 猜测一个不同 Run。

面板与聊天摘要消费同一个 `teamChat.run` 快照。`TeamChatController` 完成刷新后调用面板 `update({team,run})`，因此面板不再建立第二条 Run 轮询。

### 打开与关闭

- 桌面首次出现未结束 Run 时默认展开；用户手动收起后，按团队记住偏好。
- 手机始终先显示摘要栏，不自动弹出抽屉遮住聊天。
- 展示偏好使用 `teamLivePanel:<teamId>` 保存 `open/closed`；Run 状态变化不覆盖用户选择。
- 收起只隐藏 DOM；已有 4 秒 Run 刷新是否继续由现有聊天逻辑决定。
- 切换普通聊天、Dashboard 或完整 Run 时隐藏；返回团队后恢复。
- 关闭面板不调用任何 Run 控制接口。

### 加载与刷新

- 首次打开显示骨架或“正在读取 Run”，保留聊天可滚动和可输入。
- 图数据仅在面板可见且 `runId` 或任务版本变化时请求；隐藏后取消过期响应。
- 轮询重绘保留面板滚动位置、选中任务、选中成员和抽屉状态。
- 临时刷新失败保留最后成功快照，并显示“刷新失败 + 最近同步时间”，不清空内容。
- 没有 Run 时显示空状态和“从聊天发送第一条团队任务”，不显示空图。

### 尺寸

桌面固定建议宽度 360–400px，聊天列设置可读的最小宽度；空间不足时先收起侧栏或转为抽屉，不让三列同时挤碎。第一版不做拖拽调宽。

## 4. 第二项：实时成员名单

### 成员行内容

负责人置顶，其余成员按团队原顺序排列，不因状态变化跳动。每行包含：

- 名称、角色和 `agentKind`；沿用 `teamMemberAgentLabel()`，避免重复名称。
- 当前状态及一个最相关任务标题；没有当前任务时显示“空闲”或最近终态。
- `available=false`、`enabled=false` 的独立提示，不抹掉该成员的历史执行事实。
- 主按钮“选择成员”和独立按钮“打开会话”，避免选择联动时意外跳页。

成员名单只汇总当前 Run，不在团队卡静态 chips 上重复实现。团队卡仍负责配置与可用性，实时面板负责本次执行。

### 确定性状态推导

按单个成员在当前 Run 中的任务计算，优先级如下：

| 展示状态 | 判定依据 |
| --- | --- |
| 需处理 | 关联任务 `failed/outcome_unknown/stopped`，或该成员存在待答问题 |
| 运行中 | 关联任务 `running/dispatching`；Lead 在 `collecting/reducing` 时也可显示运行中 |
| 就绪 | 关联任务 `ready`，但尚未进入执行 |
| 等待依赖 | 关联任务 `planned`，且仍有未完成前置 |
| 已完成 | 关联任务全部正常完成 |
| 空闲 | 当前 Run 没有该成员的活动任务 |

未知任务状态归入“需处理”，保留原始状态文本供排查。状态不是账号在线状态，不使用“在线/离线”措辞。

### 当前任务选择

每个成员只展示一条最相关任务：需处理优先，其次运行中、就绪、等待依赖，最后最近终态；同优先级保持服务端任务顺序。完整任务数量以“另有 N 项”表示，点击成员后在图中全部高亮，不隐藏或重排图节点。

### 与会话的衔接

“打开会话”复用 Run 任务卡现有的解析顺序：

```text
result.sessionId
→ task.dispatchSessionId
→ executionThreadId 对应 thread.providerSessionId
→ member.sessionId
```

提取共享 helper 供实时面板与 `TeamRunScreen.renderTask()` 共用，避免两处跳转口径漂移。打开执行会话时携带 `{teamId,runId,taskId}` 来源，沿用“返回 Run”；若用户从实时面板进入，则返回团队聊天并恢复面板，而不是强制打开完整 Run。

无可用会话时禁用按钮并说明“该任务尚未绑定执行会话”，不跳到其他成员会话兜底。

## 5. 第三项：任务 DAG 联动

### 复用现有图

保留 `teamGraphLayout()`、Dagre 节点坐标、SVG 连线和窄屏分层回退。实时面板使用相同 graph 数据构造紧凑视图；完整 Run 页继续显示原图，二者共享关系计算，但不共享 DOM。

### 单一选择模型

```text
pinnedSelection = null | { kind: "task", id } | { kind: "member", id }
previewTaskId = null | string
```

- 鼠标悬停或键盘聚焦任务只设置 `previewTaskId`，用于临时预览。
- 点击任务固定选择；再次点击或按 `Escape` 清除。
- 点击成员固定成员选择，并高亮其全部任务及这些任务的直接关系。
- 新选择替换旧选择，避免“成员筛选”和“任务筛选”叠加后无法解释。
- 轮询只更新状态，不改变选择；任务已不存在时清除选择并显示普通图。

### 上下游高亮

根据 `dependsOn` 用带 `visited` 的遍历计算祖先与后代，异常环不得导致死循环。选中任务时：

- 选中节点：实线粗边框。
- 上游节点与边：实线高亮，表示“为什么能/不能到这里”。
- 下游节点与边：虚线高亮，表示“完成后影响哪里”。
- 无关节点：降低强调但仍可读，不从布局删除。
- 边通过 `data-from/data-to` 与节点关系对应，不能重新按数组下标猜依赖。

成员选择采用其任务集合的并集；选中项说明中列出任务数量，不把多个任务误拼成一个任务标题。

### 选中项解释

任务详情至少包含：任务标题、负责人、状态、直接未满足前置、直接下游。文案规则：

- 有未完成前置：`等待：任务 A、任务 B`，可点击跳到对应前置。
- 前置全部满足：`前置已满足`，但不据此伪造正在运行。
- 有下游：`完成后解锁：任务 C`；多下游完整列出或折叠展开。
- 无下游：`没有下游任务`，不写成“即可交付”。

### 跳转与定位

- `定位任务`：打开完整 Run，加载后调用现有 `revealTask(taskId)` 滚动并高亮任务卡。
- `打开会话`：使用第 4 节共享会话解析，保留来源。
- 点击依赖任务名称：只改变选中项，不直接跳页。
- 手机分层列表使用同一选择模型和解释区，不要求绘制复杂 SVG。
- 图横向滚动区域可键盘聚焦；所有任务节点都是原生 `button`，状态不能只靠颜色表达。

## 6. 状态、数据与前端结构

### 数据来源

| 数据 | 现有来源 | 用法 |
| --- | --- | --- |
| 团队与成员 | `GET /api/teams` | 名称、角色、Agent、可用性、成员会话 |
| 当前 Run | `GET /api/teams/:teamId/runs` + `/:runId` | 由 `TeamChatController` 统一选择与刷新 |
| 任务关系 | `GET /api/teams/:teamId/runs/:runId/graph` | 节点、依赖、负责人、结果摘要 |
| 执行会话 | Run `tasks/threads` + member `sessionId` | 打开真实任务会话并保留来源 |
| 展示偏好 | `localStorage` | 每个团队的展开/收起状态 |

第一阶段不新增后端接口。如果现有 graph 节点缺少任务状态或 `memberId`，优先复用 Run detail 按任务 ID 补充展示，不另造接口；确实无法对齐时才扩展既有投影，并增加 Go 测试。

### 新增与调整文件

- `web/team-live-panel.js`：新增 `TeamLivePanelController`，负责面板渲染、成员状态、图选择和过期请求防护。
- `web/index.html`：在 `#chat` 同级加入 `#team-live-panel` 与手机摘要栏，引入新脚本。
- `web/team-chat.js`：刷新后向面板推送同一 `team/run`；不新增 Run 请求。
- `web/app.js`：面板显隐、打开成员会话、完整 Run 定位、返回来源和团队切换。
- `web/team.js`：提取任务会话解析与图关系 helper；`openTeamRun` 增加可选任务锚点。
- `web/style.css`：桌面双列工作区、手机底部抽屉、选择与高亮状态。
- `web/i18n.js`：新增中文文案的英文词条。
- `site/demo-product/web/`：生产行为稳定后同步对应演示实现，避免演示与真实产品结构继续漂移。

### 控制器接口

```text
open(team)                         打开团队并恢复展示偏好
update({ team, run, error })       接收聊天控制器的同一快照
loadGraph(runId)                   可见时读取/刷新图
select({ kind, id })               固定成员或任务选择
preview(taskId|null)               悬停/聚焦预览
close()                            只收起展示
destroy()                          清计时器、作废请求、解除事件
```

`app.js` 持有跨页面来源与路由，控制器不直接写 `location.hash`。所有异步回调携带 generation；切换团队、Run 或关闭后，旧响应不得覆盖新视图。

### 可测试的纯函数

- `teamMemberRunState(member,run)`：成员状态与最相关任务。
- `teamTaskSessionId(task,detail,member)`：统一会话解析。
- `teamGraphRelations(nodes,selected)`：祖先、后代和相关边。
- `teamSelectionAfterRefresh(selection,nodes)`：刷新后保留或清理选择。

这些 helper 采用现有 CommonJS 导出方式，供 Node 测试和浏览器复用。

## 7. 响应式、可访问性与异常状态

### 响应式规则

- `>1100px`：侧栏、聊天、实时面板三列；面板 360–400px。
- `721–1100px`：默认收起面板，通过聊天头部“当前 Run”以右侧抽屉打开，避免压缩聊天。
- `≤720px`：聊天全宽 + 底部摘要栏；点击后底部抽屉最高占视口约 75%，内部滚动。
- 抽屉不遮挡输入区的焦点与键盘；手机软键盘弹出时收起抽屉，返回聊天后保留摘要栏。
- 长目标、长成员名和长任务标题最多两行截断，完整文本通过 `title` 或详情查看。
- 页面主体不得产生横向滚动；只有图区域允许自身横向滚动。

### 可访问性

- 桌面面板使用 `aside`；手机抽屉使用非模态 `role=dialog`、`aria-modal=false`，不锁死聊天。
- 打开手机抽屉后焦点进入标题或关闭按钮；`Escape` 关闭并还原到摘要栏触发按钮。
- 成员和任务使用原生按钮，选中状态用 `aria-pressed`；临时预览不频繁触发 `aria-live`。
- 固定选择后的等待/解锁说明通过 `aria-describedby` 关联，不重复朗读整张图。
- 状态同时有文字和形状，不依赖颜色；减少动态效果模式下无平滑滚动和脉冲动画。

### 异常与空状态

| 场景 | 展示与动作 |
| --- | --- |
| 团队没有 Run | 显示引导，不显示成员执行状态或空图 |
| Run 有任务但 graph 404 | 使用 Run detail 回退分层列表，联动仍可用 |
| graph 请求失败 | 保留成员与 Run 摘要，图区域独立重试 |
| 成员无执行会话 | 禁用会话按钮并解释未绑定，不跳错会话 |
| 选中任务在新快照消失 | 清选择、保留面板，提示任务列表已更新 |
| 成员不可用或停用 | 保留其历史任务，附加配置状态，不改写执行结果 |
| Run 等待输入或失败 | 下一步置顶，相关成员与任务默认高亮，但不自动跳页 |
| 刷新或路由过期响应 | 按 generation 丢弃，不覆盖当前团队 |

所有错误都保留可继续操作的区域；不能因为图失败而让聊天和成员名单一起失败。

## 8. 实施顺序与验收

### 阶段 A：常驻面板骨架

1. 增加 DOM、控制器和桌面/手机布局。
2. 复用 `teamChat.run` 渲染头部、进度、下一步和完整 Run 入口。
3. 接入每团队展示偏好、切换团队清理和过期响应保护。
4. 完成空、加载、失败、终态和等待输入状态。

验收：活跃 Run 无需离开聊天即可看到一致进度；关闭不影响执行；桌面与手机刷新不丢滚动位置。

### 阶段 B：实时成员与会话跳转

1. 实现成员状态纯函数与成员行。
2. 接入成员选择和“打开会话”。
3. 提取共享会话解析，替换 Run 任务卡原逻辑。
4. 验证无会话、不可用成员、多任务成员和 Lead 收尾状态。

验收：任一成员状态可由任务快照解释；任务会话跳转与 Run 详情一致；返回后来源和面板状态正确。

### 阶段 C：图与任务联动

1. 在实时面板接入 graph，窄屏复用分层回退。
2. 实现预览、固定选择、祖先/后代和相关边高亮。
3. 增加等待/解锁解释与成员—任务双向选择。
4. 扩展完整 Run 的任务锚点，返回后恢复选择。

验收：复杂分支、环防御、未知依赖、选中任务消失均不破坏页面；键盘可完成同样路径。

### 最终端到端验收

1. 从团队聊天发起包含并行任务的 Run，面板自动出现且聊天仍可输入。
2. 选择正在执行的成员，图只高亮其相关任务；打开会话能看到真实执行回合。
3. 返回团队聊天，选择被阻塞任务，可看到直接前置和下游。
4. 打开完整 Run 定位同一任务，查看结果后返回，面板选择仍保留。
5. 切换到另一团队再返回，不出现旧数据；手动收起的团队不会被自动重新展开。
6. 断网刷新时保留旧快照与错误提示，恢复后状态收敛。

## 9. 默认决策与后续边界

以下默认决策用于避免实施时重新争论；评审可推翻，但应同步修改线框和验收：

1. **只做单方向**：桌面右侧常驻、手机底部抽屉，不再同时设计浮动窗口方案。
2. **面板跟随团队聊天**：不跟随任意成员会话；成员会话属于三级证据查看。
3. **优先当前未结束 Run**：与现有聊天摘要完全一致，不提供面板内 Run 切换器；历史 Run 从 Dashboard 或完整详情进入。
4. **选择而不是过滤**：图联动只高亮，不删除节点、不自动缩放、不改变布局。
5. **成员行不直接跳页**：选择与会话是两个动作，防止查看联动时丢失聊天上下文。
6. **手机不自动展开**：只显示摘要栏，由用户主动打开抽屉。
7. **固定宽度优先**：第一版不做拖拽调宽和位置持久化。
8. **不新增后端真相源**：前端只组合现有 Run、graph 与团队投影；状态规则由确定性函数统一计算。

### 留到后续评审

- 成员未读消息、模型与 reasoning effort 展示。
- 面板内切换历史 Run、暂停/恢复/转发等控制动作。
- 运行前计划审批、团队归档。
- 角色头像、职业插画和状态动画。
- 面板拖拽调宽、浮动窗口及位置持久化。

线框中的灰度边框、密度和图标仅为结构占位；最终颜色、字体、间距与图标沿用现有产品样式，不在本轮线框评审中决定。

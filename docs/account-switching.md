# 账号与接入

多账号与 API 接入管理自旧版本线 v1.3.0 起提供。账号添加仅在 Bridge 桌面端进行，已保存接入可在桌面端和 Web 切换。

## 添加与管理

启动 Bridge 网关，在 **Bridge 桌面端 → 账号与接入** 操作：

- **官方 ChatGPT 账号**：填写名称，继续后点击“打开官方登录”，在此电脑的浏览器完成授权。添加过程使用独立登录目录，不替换当前 Codex 认证。支持取消登录、重命名和重新登录。
- **自定义 API**：填写名称、API 地址、API Key 和默认模型。服务需要兼容 Responses API。远程地址使用 HTTPS，本机服务可以使用 HTTP。修改已有 API 时，密钥留空表示保留原密钥。
- 当前接入不能直接删除、修改或重新登录，先切到另一个接入再操作。
- 网页没有添加、修改、删除或恢复接口。登录链接也不发送给网页。

### 扫描已有配置

展开 **扫描本机配置**，留空使用运行配置中选定的 Codex 数据目录，也可以填写其他 Codex 配置目录。点击“扫描配置”后，选择要导入的官方账号或 API。扫描和导入不切换当前账号、不重启 Codex；导入后仍需显式选择切换。

扫描识别 `auth.json` 中的官方登录、原生 API Key，以及 `config.toml` 的 `model_providers` 和 `profiles`。API 密钥可来自直接保存的 bearer token 或 Bridge 进程已有的环境变量；缺少密钥、非 Responses 协议及额外请求头/认证配置会显示不可导入原因，避免导入不完整的接入。系统凭据库中的官方登录不直接复制，使用“官方 ChatGPT 账号”重新授权添加。重复导入相同账号/接入不会重复创建。若导入的接入就是当前接入，会自动标记并禁用切换按钮，无需再次切换。

API 配置选择后填入添加表单，保存的密钥不显示；可获取上游模型或手填模型，再点击“继续”完成导入。如果扫描后修改了源配置，请重新扫描。

### 从上游获取模型

在自定义 API 表单填写 API 地址和 Key，点击 **获取上游模型**，然后从列表选择默认模型。已有 API 修改时密钥留空可使用已保存密钥；扫描出的 API 使用后端暂存的凭据，无需把 Key 填回界面。

此操作只在手动点击时请求该 API 地址下的 `GET /models`，不发送推理请求，也不自动跟随重定向。上游不支持列表、拒绝访问或返回空列表时会显示原因，仍可手动填写模型。列表中的模型未必支持 Responses API，需要用实际对话验证。扫描、导入和填写任意地址的模型查询仅在桌面端提供；Web 可查看已保存接入的模型。

网页进入 API 聊天后，模型选择器按该聊天的提供商和工作目录配置读取上游 `GET /models`，不再使用官方 GPT 目录。旧模型不在上游列表时会提示重新选择，点击“应用”后才修改聊天模型；读取列表本身不更改聊天设置。查询失败时显示原因，并保留手动填写模型 ID。官方账号继续使用原生模型目录，SSH 聊天在对应主机查询。

### 当前接入、额度与模型

两端会识别当前 Codex 的有效接入，并在匹配的账号旁显示不可点击的“当前接入”。尚未保存的接入会单独标明；识别失败时显示暂未识别，不沿用旧账号标记。

桌面与 Web 均将当前接入置顶，并禁用其切换按钮。官方账号名称旁显示紧凑的剩余额度进度条与重置卡数量；API 接入不显示官方额度。各账号均可展开“查看可用模型”。

首次打开账号页面会自动查询官方账号额度，无需点击；后续在页面可见时每五分钟更新。手动点击“查看剩余额度”立即查询，并从本次查询完成后重新计时五分钟。离开页面或隐藏网页后停止查询，后台账号列表读取不触发首次额度查询。桌面与 Web 自动查询共用后端五分钟缓存。额度查询与使用重置卡是不同操作。

Web 侧栏只有一个固定位置入口：官方登录显示“账号与额度”，API 显示“API 接入”，均打开账号列表；当前官方账号的重置卡详情也在同一面板内。

桌面端原“账户与额度”已并入“账号与接入”。当前官方账号的完整额度恢复时间和重置卡操作保留在折叠的“当前账号 · 重置卡与额度详情”中。使用卡片仍需确认，能否使用由官方账号能力与设置决定。

首次使用请在“桌面程序与恢复”核对 **桌面程序路径**。这里选择的是 Codex / ChatGPT GUI 的实际可执行文件，不是内置 Codex CLI，也不是 shell 启动脚本。macOS 通常可自动发现应用包内程序；Windows 和 Ubuntu 的非标准安装可能需要手动指定。

## 切换

桌面端可直接选择账号；Web 首页通过“账号与接入”选择已保存账号。两端切换的是此电脑同一份认证与默认提供商配置。

切换前结束所有桌面任务，包括没有在网页显示的任务；清理排队消息和未确认的发送。确认后会依次准备配置、退出官方桌面应用、应用接入、启动并核验。Bridge 网关保持运行，切换期间暂停聊天写操作、排队发送和主动激活。免密访问模式不能从网页切换账号。

阻止切换时会列出运行中、待确认、排队或发送结果未确认的聊天。已断开的旧状态和连接错误本身不会被当成运行任务；这不代表能检测到所有未接入网关的桌面任务，仍须在确认前检查桌面。

- **官方 A → 官方 B**：保留聊天历史，下一次消息使用重新启动后的认证。账号所属工作区和权限仍以官方运行时为准。
- **官方 → 自定义 API**：切换同时写入原生 API 登录状态、默认提供商与 `openai_base_url`，让桌面继续选择 `openai` 的聊天也使用所选 API 地址。默认 API 提供商使用 HTTP Responses 协议。已有聊天仍保留原 provider，不改写历史数据库；其他自定义 provider 的聊天需要切回对应接入。
- **API → 官方**：移除 Bridge API 与 `openai_base_url` 配置并恢复官方认证。原 `bridge_api` 聊天需要切回 API 或新建官方聊天。已有 `forced_login_method` 会同步调整为目标登录方式。
- **SSH**：不改远端认证；本机桌面重启期间，SSH 聊天界面连接也可能短暂断开。
- 当前模型、Fast、额度和重置卡仍受真实账号及工作区能力限制。账号添加成功不等于 API 模型请求已验证成功。

如果配置启用了不能安全覆盖的 profile 或组织策略，切换会失败，需先在官方桌面端解决配置限制。macOS 首次退出应用可能需要系统允许自动化控制。Ubuntu 应在已登录的图形桌面会话中启动 Bridge。

## 失败与恢复

切换前保存配置与认证快照。目标账号或桌面连接核验失败时，尝试恢复原接入并重启。若进程中断或自动恢复失败，聊天操作保持暂停；在 Bridge 桌面端选择“桌面程序与恢复 → 恢复原接入”。不要在恢复期间同时手动编辑认证文件。

“切换完成”表示新的本地认证、有效提供商配置和桌面 IPC 已核验；没有为此自动发送付费模型请求。真实模型响应仍需用户自行测试。

## 数据保存

账号档案位于 Bridge 数据目录的 `accounts/`，使用 Codex 原生文件认证格式。目录和文件限制本机文件访问权限；不是额外的加密保险库。OAuth 令牌、API Key 和恢复快照不会返回 Web、写入命令行参数或显示在界面中。请不要共享或提交这个目录。

当前 Codex 数据目录保持不变，仅替换 `config.toml` 和 `auth.json`；聊天数据库、历史、项目和 Skills 不搬迁。配置由官方运行时的配置接口生成。官方账号离开前保存已刷新且身份匹配的凭据。

## 本轮验证范围

已覆盖模拟切换、回滚、中断恢复、登录完成与取消、重复请求、任务/队列阻塞、HTTP 权限边界和界面竞态。真实运行时仅在隔离目录验证了提供商配置写入/删除与无关设置保留，未调用模型推理。

已用桌面内置 Codex 0.160.0 和本地模拟上游验证 API 登录、新聊天、显式 openai 提供商聊天与恢复旧聊天的实际 `/responses` 地址及 Bearer 认证。真实官方账号 A/B 切换、真实第三方 API、重置卡消费，以及 Windows / Ubuntu 真机的退出启动与系统权限，仍需用户测试；不能将模拟测试或 macOS 打包通过视为三平台实机通过。

旧版已经处于 API 接入时，新配置会在下次切换到该接入时写入；可先切到另一接入，再切回来。当前账号按钮仍保持禁用。

## Computer use 授权

Web 根据桌面请求实际支持的范围显示“始终允许”“拒绝”“允许此对话”，以原生 MCP elicitation 的 `_meta.persist` 回传。后端对照仍待处理的原请求校验范围；普通表单不能附带持续授权，已过期请求不能再次授权。允许本次不会被静默扩大为持续授权。

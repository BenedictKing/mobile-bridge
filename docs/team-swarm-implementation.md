# Swarm Riding 实施记录

状态：本地执行版已实现，2026-11-12。设计见 [目标设计](team-swarm-riding-design.md)。

## 顺序与依赖

1. S0：默认关闭的 Team 策略、Run 策略快照、执行前契约、持久化与即时内容指纹。
2. S1：实际候选快照、独立目录评测、明确结果归因、证据投影。
3. S2：独立审查门禁、有限修复、重复失败与跨修订预算。
4. S3：预备工作区上的并行候选、集成检查与目标门禁。
5. S4：自动供给是可选后续；本轮不创建/删除用户分支或 worktree。

先实现后端纯判定及恢复，再接 HTTP、Lead 协议与现有页面；前端沿用现有样式。

## 验证计划

- 定向测试覆盖冻结条件、幂等、版本冲突、重放、证据失效与自审。
- 临时 Git 仓库验证真实候选、未跟踪内容、评测 cwd、超时取消与集成冲突。
- 修复测试覆盖两次上限、重复错误、修订不重置及共享任务归属。
- 全仓 Go test/vet/build、相关 race 和现有 Node 测试。
- 隔离数据及端口，用 ego-browser 检查桌面和手机操作与结果，不操作真实团队。

## 环境与兼容

- 起始 HEAD：ab1a0e24，main，工作区干净；当前不是辅助 worktree。
- 原生 JavaScript，Node 和 Go 可用，前端测试不依赖额外包管理器。
- 旧 Run、旧队列及审批语义保留；新策略仅影响显式启用后的新执行。
- 本地快照不等于 OS 沙箱；能力和证据等级必须如实展示，保留人工确认。

## 回滚

停止新准入与自动修复，保留在途收账、契约、候选和 journal；未知外部结果不自动重发。
不删除工作区、不撤销用户修改、不自动重启现有网关。

## 结果

已接通默认关闭的 Team 设置、Run 策略快照、Lead 契约提案与用户接受、不可变契约及原话范围、专用执行/审查会话、真实候选与字节差异、独立评测、有限修复、集成和既有目标确认。旧执行及旧证据哈希保持兼容。

新增 `internal/swarmeval` 只操作受管理制品；不创建分支或 worktree，不改源 index，不合入主工作区。评测在独立副本运行固定 argv，记录工具身份、内容、日志、时间及进程；准备失败与断言失败分开。Unix 支持取消进程组；其他平台评测拒绝执行，不能伪装已通过。

修复最多每条件两次，重复失败停靠，次数与期限沿修订链累计；格式修复独立计数。审查缺失/自审/产物被修改均不能通过。新原话使旧契约范围失效，需修订；评测结果未知不得自动重跑。journal 已接受但快照落后时先恢复操作身份，任务与产物关系同批恢复。

## 本版范围

- 使用用户预备的同库工作区和受管理快照；集成按文件保守组合，同文件冲突拒绝并提示处理。
- 本地快照隔离工作副本；没有 OS 文件/网络沙箱，写入范围主要通过实际变更检查，最终目标仍保留用户确认。
- 阈值由冻结检查命令中的断言表达；不包含通用指标表达式、模型排行榜或训练奖励。
- 契约绑定 Run 并进入既有事项目标条件；共享运行的必要集成检查仍保守作为共同交付门禁。独立 scope 级自动验收和自动工作区供给不在本版开放。
- 依赖准备识别根目录 npm/pnpm/yarn 与 Go 锁定入口；monorepo 子入口、bun 和非 Unix 的执行能力未开放。缺能力明确显示环境原因。

## 使用

团队设置启用“目标契约与评测（仅新运行）”，发送目标；在 Run 详情接受负责人提案或填写完成条件、固定命令参数、写入范围及预算。原始要求不可删除。完成后查看候选差异和检查证据，使用原“确认符合要求／反馈问题”入口处理最终结果。

# Codex 迁移的官方 CLI 接管

2026-11-20，本机 App 26.1117.31558 没有监听网关依赖的旧桌面 IPC。
目标线程已经创建并被 App 打开，迁移正文仍停在 `waiting_for_target`。
新版 App Tools 通道拒绝缺少所需代码签名身份的网关进程。
用户确认允许官方 CLI 接管迁移后的执行。

## 接入方式

- 旧 IPC 可用时继续使用原桌面 owner。
- 旧 IPC 不可用时，仅未派发的迁移切换到官方 `codex app-server`。
- 沿用目标线程 ID、Codex 数据目录、模型与思考强度。
- 连接前核对线程 ID、cwd、provider；cwd 校验支持 macOS 路径别名。
- 未加载的线程若仍有执行中的历史回合，拒绝接管，要求核实原运行时。
- 执行归属写入创建账本，启动时恢复路由；列表读取不会批量恢复线程。
- 专用 Unix socket 位于数据目录的 `codex-cli.sock`；运行时不随网关连接关闭。
- 启动锁避免多个网关重复拉起；已有 socket 协议错误不会触发替换进程。
- 此接管路径适用于 macOS/Linux；Windows 继续使用桌面 IPC。

## 发送与交互

迁移、重新连接共用创建账本及确定性消息 ID。发送前持久化 `dispatching`，
超时或断线保留不确定状态，禁止自动重放。重启网关后接入同一 socket，
不会新建线程或重复注入正文。

CLI 的回合、消息、工具、token 用量和审批进入现有时间线与通知投影。
发送、Plan、steer、停止、模型设置、附件、原生审批和异步问题可继续使用。
CLI 模式暂不提供原桌面的原地编辑、分支和 Goal 控件。

未发送的迁移在刷新后持续显示“正文已保存”；不确定发送持续显示待确认。
聊天详情标明由本机 Codex CLI 执行。桌面 App 可查看同一线程的保存历史，
执行期间应由手机/CLI 操作，避免同时在桌面提交回合。

## 验证与加载

官方 CLI 的隔离检查覆盖空 rollout 创建、恢复、设置及断开后的同线程重连，
不向真实模型发送测试提示词。HTTP/Unix socket 回归覆盖迁移、重复请求、
未知发送、审批回应、事件乱序和持久化路由；前端 Node 测试全部通过。

最终 `GOFLAGS=-p=2 make check` 的 build、vet、全量单测及完整竞态检测通过。
320 项前端测试、Windows 交叉构建通过；ego 隔离页面验证刷新后的等待提示、
不确定发送提示，以及完成后隐藏提示和 CLI 执行归属。默认并发首轮曾遇到
既有团队闸门测试超时，其原始 ACP 代码 overlay 单独回归通过。

需要用户自行重启网关加载后端与嵌入资源，再刷新原迁移对话。
原迁移的模型端送达及真实手机验收尚待加载新版本后验证。

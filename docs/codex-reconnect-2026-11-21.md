# Codex 普通聊天重连修复

## 本机证据

2026-11-21，桌面 App 26.1117.31558 正在运行，网关也已重启。
网关依赖的 `~/.codex/ipc/ipc.sock` 文件仍在，但没有进程监听，实际连接返回 `Connection refused`。
网关此前把所有拨号失败都提示为“请打开 Codex App”，无法说明 App 已打开却接口不可用的情况。
此前的 CLI 接管仅覆盖登记过的迁移目标，普通桌面对话在网关重启后仍尝试旧接口。

## 修复行为

- 普通聊天发送、激活重连及已有排队消息共用接入函数，复用官方 CLI 运行时。
- 仅 socket 缺失或拒绝连接时允许选用 CLI；桌面握手、权限等错误不会触发替换执行方。
- 沿用同一聊天 ID，先读取保存历史确认工作目录，再持久化 CLI 执行归属。
- CLI 接入继续核对 ID、cwd 和 provider；尚未加载且历史显示执行中的线程拒绝接管。
- 网关启动恢复执行路由，不提前恢复线程；GET 历史读取不会给未登记聊天选择 CLI。
- 手机打开聊天会发出已有的激活重连请求，此时只接入所选聊天。
- 不重复发送旧消息；断线后的不确定发送保留消息账本，重启后相同消息 ID 仍去重。
- 连接前明确拒绝的发送记为失败，不误标为可能已送达。
- 确认未派发的失败草稿可使用原消息 ID 重试，并发重试只领取一次；不确定发送不适用。
- 时间线沿用已有“由本机 Codex CLI 执行”提示及 CLI 能力限制。

执行由手机/CLI 控制；桌面可查看同一线程保存的历史，执行期间避免两端同时提交回合。
实现复用现有 CLI、创建账本和消息账本，只增加共享接入函数，避免两套恢复和去重逻辑。

## 聊天标题

新版 Codex 的 `name` 保存显示标题，`title` 可能仍是首条消息。
列表优先使用非空 `name`，再退回 `title`；列表发现也使用相同规则，桌面改名后能刷新。

## 空闲写入权交接

手机接入的 CLI 会话空闲 30 秒后，网关定期检查原生运行时；只有线程空闲、没有待处理请求、后台终端或活跃子 Agent 时才取消订阅。状态未知或检查失败时保留占用并稍后重试。官方 app-server 在最后一个订阅者退出后，默认等待 60 秒再卸载并释放写入锁；其他订阅者仍在时不会提前释放。

历史读取和事件流不会恢复线程或延长写入权。手机再次发送时恢复同一线程；恢复和写操作与释放互斥，未确认的发送不会重放。界面显示空闲释放状态及发送时重新连接的提示。

网关只能释放自己持有的订阅，无法关闭桌面 Codex 持有的会话。桌面持有写入锁时，需要先在桌面关闭对应会话并等待卸载，再从手机重试。锁文件由 Codex 管理，不要手工删除。
